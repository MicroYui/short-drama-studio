# 短剧视频编译方法

## 当前事实与有序引用

从当前生成组的逐镜设计、对白、时间窗和实际媒体编译。引用只承担已声明的身份、空间、道具状态、构图、动作或声音。COMPOSITION 在 REFERENCE 中指导构图与状态，不承诺复制像素；FIRST_FRAME / LAST_FRAME 只约束整次请求首尾，不能当组内逐镜/逐beat帧槽，也不能与多参考混用。人物多视图是同一人，拼图不代表分屏；保持代码绑定与顺序，剪辑图版不混入生成输入。

同装或外观近似的多角色组，绑定标签之外还保留 brief 或已观察素材支持的可见区别，如发型、脸部轮廓、体态和配饰，并对应各自出现时窗。没有图像观察时不臆造区别。主角身份描述不能弱到只剩“提取该图身份”，而配角具有更醒目的具体外貌；引用是否清楚需按实际图像核对，复杂多视图卡不一定优于一张清楚的当前身份图。

本方法只补充叙事与表演判断。字段、图片标签、帧对齐及长度由当前 Provider 编译合同提供；不带 Design Hub 的固定中文首尾句、默认光圈和摄影风格。稳定身份、空间、声音集中定义，逐镜仅写发生的变化，不逐镜重述全部参考。

## 连续表演与角色声音签名

将每镜写成可读的事件：当前起点和镜头 → 触发动作 → 人物可见反应 → 原文对白或行动 → 对方回应与结束状态。只保留剧情需要的视线、呼吸、手势、身体反馈及运镜。角色声音签名来自项目已有声音方向，保持本组实际说话人的音色与语言连续；对白时写当前情境的语气和停顿，不凭空添加台词、口音或独立音轨。

画面里的面部颜色变化表达为局部、渐进的生理反应，避免把文学性的“脸红、煞白”放大成整脸变色。正反打要说明机位侧、前景人物、目标和背景关系，不将同一人的参考角度写成额外角色。

## 真实连续性与修复

计划终态表达意图，真实采用片段的末段观察表达已发生事实。只承接本镜确实依赖的持物、位置、动作或声音边界；没有观察时明确未知，不能宣称上一镜已兑现。可以使用合适的真实末帧锚定连续动作，但无依赖镜头不用等待前镜生成。

正常例：已选图规定人物与窗口位置，文字写“男生轻推餐盘，松手后望向阿姨；阿姨低头看盘再抬眼”，台词逐字置于自己的时间窗。失败例：同一时段同时要求双手交钱、转身离开、阿姨验算、旁人抢话和大幅绕拍；返回具体动作或空间冲突给导演，不能靠删台词、合镜或更多形容词强行编译。

正常失败例：两名同装人物的参考均已绑定，生成后主角却继承配角的发型与脸。先核对实际扮演关系与引用清晰度，保留有依据的身份差异、减少无关主体竞争；需要新候选时只处理受影响组，不默认添加更多图片，也不因技术回收成功而认定身份通过。

若只是超长，保留全部不同事实与对白，只精简当前超长字段的重复修辞；传输重试复用已成功的 Prompt 和引用，不重新编译。剪辑层可解决的精确文字或停顿不扩展成整组再生成。
