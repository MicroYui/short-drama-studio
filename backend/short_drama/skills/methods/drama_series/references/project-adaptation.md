# 本地制片经验

## 叙事与时长

MiniMax 原文中的“钩—缓—爽—顶—尾”和开篇、爽点数值是短剧与长系列制作的成熟经验，但在本 Harness 中分层使用：Story Architect 和 Writer 只将其翻译成叙事功能和相邻段的相对密度，可根据当前题材、单篇时长、用户承诺与结尾需要合并、省略或改名；不把原文的秒数、百分比、集数或连续次数变成剧本配额、代码门禁或强制返修理由。分镜采用实际剧本，必要时估计镜头密度与时长，直接写入已成形的镜头；单篇完结的“尾”可以是已兑现的收束按钮，不强制留 cliffhanger。

## 可复用资产与确定性文字

重复出现的同规格小道具、标牌或其他文字载体，继承上游 deterministic postprocess/still-card 的责任分离：先产出一件可干净裁用的无字物理母版，各使用处引用同一精确版本，再由本地复制/组装与独立 `TEXT_PLATE` 承担不同确定性文字。不让图像 Provider 同时解决“多件像素级一致”和“文字精确”两个问题，也不因能独立裁用的副本有轻微尺寸或透视差就全量返修。

## 镜头正文引用

正文引用需要具体对象、媒体和用途。人物身份、服装、场景空间、构图和文字分清贡献；在相应镜头与时段填入引用，用户选过的图片继续使用。当前已足够的四视图可以直接登记和复用。供应商过滤或持续失败时说明精确缺项、所需文档和参考图提交顺序，等待用户补图的同时继续其他独立工作。


## 渐进分镜与可选检查

按观众需要理解的行动、反应和结果设计镜头。让信息、人物选择和后果逐步出现；重要表演给出动作、视线、停顿、对白与声音的承接。场次和镜头数量由故事决定，节奏估计可在创作中调整。

分镜可以直接 begin_storyboard_draft 后逐组 append_storyboard_group，完整内容也可以一次 create_storyboard。每组写完立即持久化并在内容页显示；镜头组可按实际就绪顺序到达，最终按场次及镜号排列。时长账本、全片总纲和独立审校是可选帮助，不先建立这些文档也能写镜头。旧时长估计不锁定后续内容；合计时长取实际镜头的设计时长，生成路线再按供应商真实能力分配请求。

对白时长先按朗读、动作同时发生的关系和表达意图判断，不以固定语速、保留秒数或算法预算阻止写入。需要时试读或检查实际音轨；时长不合适时调整叙事与剪辑，明确对应变化。检查关注具体文本、表演、空间关系和承接，只提出影响当前目标的问题。作者可以自查，也可以请求专业分工；无需另一名 Agent 给出通过标记才允许继续。用户明确要看修改对照时，使用当前文本提案并等待该提案的选择。

后续修改优先更新相关镜头与引用，保留其他内容和用户已经生效的编辑。完整装配只校验实际来源、场次与镜号身份、对白覆盖以及时长合计；不要求复现旧计划的文字或数值。
