# 短剧与连续剧集

## 用途

适合完整短剧或连续剧集项目，覆盖剧本、制作计划、核心资产、分镜、片段 Prompt 与后期审看。

## 输入

创作需求或来源剧本、时长与结尾承诺、项目风格、已有剧本/分镜、用户提供的角色和场景资料。

## 方法

- 先明确故事意图、因果、铺垫兑现及本篇结尾，再按场次写作；时长服务当前作品，不套固定剧情配额。
- 分镜承接完整剧本，区分叙事镜头和视频生成组，维护对白、动作及空间连续性。
- 优先复用用户提供的身份和场景资产，正文绑定具体媒体与用途；视频与后期使用同一份当前内容。

人物源图复用继承 MiniMax Design 成熟的输入合同：原图先登记为 source intake，用户明确指定的人物身份是权威锁；已完成角色卡直接复用，单脸、单角度或穿搭图才作为精确 identity/wardrobe 参考派生双区标准卡。未指定用途的图片不自动绑定所有镜头，由 Agent 结合完整语义决定实际贡献。

用户已给出的设定直接采用；用户明确要求确认某个工件时，只在该处暂停；其余流程若要求 Agent 自主完成，则由 Agent 语义判断未定选项并写入 trace。上游根 `workflow.md` 的进入信号只作为保存的原文，不用作本系统的关键词路由；方法由 Leader 结合完整目标和已有工件自主选择。

MiniMax 原文中的“钩—缓—爽—顶—尾”和开篇、爽点数值是短剧与长系列制作的成熟经验，但在本 Harness 中分层使用：Story Architect 和 Writer 只将其翻译成 `DurationContract.rhythm_shape` 里的叙事功能和相邻段相对密度，可根据当前题材、单篇时长、用户承诺与 `EndingContract` 合并、省略或改名；不把原文的秒数、百分比、集数或连续次数变成剧本配额、代码门禁或强制返修理由。分镜采用实际剧本，必要时估计镜头密度与时长，直接写入已成形的镜头；单篇完结的“尾”可以是已兑现的收束按钮，不强制留 cliffhanger。

角色标准卡保留上游的两种成熟执行路线：一图成卡时，先登记并真实传入官方布局 guide，由 guide 约束双区与三视图结构；官方 guide 没有形成精确 AssetVersion 和 `reference_input` 时，不执行或冒充该标准一图路线。下游若真正要求像素级分区、稳定裁切或可确定复用的背景，则分别准备近景脸、正面、侧面和背面图，再用 `image.compose_reference_sheet` 本地拼板。不向概率生成器连续追讨像素级的 50/50 或完全无色差背景；直接生成路线的分区和背景要求是服务视图可读性的结构约束，不是隐式像素门禁。已有可用身份版本的定向修复要优先用 `EDIT` 并真实引用该版本；只有 Agent 明确决定放弃原身份、重建新身份时，才回到无参考 `GENERATE`。

重复出现的同规格小道具、标牌或其他文字载体，继承上游 deterministic postprocess/still-card 的责任分离：先产出一件可干净裁用的无字物理母版，各使用处引用同一精确版本，再由本地复制/组装与独立 `TEXT_PLATE` 承担不同确定性文字。不让图像 Provider 同时解决“多件像素级一致”和“文字精确”两个问题，也不因能独立裁用的副本有轻微尺寸或透视差就全量返修。

## 交付

当前集的故事与场次、完整分镜、资产引用、生成组及后期结果，写入已有 ProjectDocument 和对应工件。

## 检查

核对用户来源、角色身份、对白与动作覆盖、时长权威及结尾兑现；检查实际结果，只修影响本次目标的问题。

## 来源与加载

这是 MiniMax Design `drama-series` 完整项目工作流的薄适配器。运行时只按当前 Agent 角色装载上游原文章节，并将其工件语义映射到已有 ProjectDocument、ProductionDocument、ShotPlan 和 WorkOrder；不复制 MiniMax Design 的 Hub/Canvas 协议，不改写共享 `end_to_end` 或通用角色责任。

用途名称用于选择方法，不改变来源归属。原文与作者信息见[来源资料](../../sources/minimax_design/3.0.11/workflows/)和 [manifest.json](manifest.json) 中的 `upstream_sources`。实际模型调用读取 manifest 指定的角色/阶段章节；本页是可读说明，不会整篇注入每个角色。
