# 创作方法编写：专业方法

## 提炼有效方法

从真实重复任务中提炼会改变决策的知识：何时选用、输入是什么、关键制作判断、输出怎样使用、如何识别常见失败。不要把单个案例的题材、时长或风格升级成所有任务规则。

先找已有方法覆盖范围。重复知识更新原章节，新用途才单建；保留专业细节，删掉通用口号、重复提醒和不存在的工具。用户目标、当前工具合同与事实优先于示例。

## 入口与渐进读取

入口写用途、必要输入、核心判断与输出；具体模式、参数、样例和故障定位放在有明确用途的参考章节。目录、ID 与标签使用用途名称，description 说明实际适用场景，不堆触发词或强制关键词路由。

每个角色只读取它需要的片段，共享知识保持一个维护位置。为特殊条件写清何时需要参考，不把全部资料作为前置阅读，也不自动把所有方法加入每次请求。

## 本项目的文件合同

当前方法使用 SKILL.md 与独立 manifest.json，声明 id、label、description、roles，以及 role_source_sections 和可选 stage_role_source_sections。POST.DIRECTOR 应读取后期内容；ASSET_PLANNER、ASSET_BUILDER 与 ASSET_VERIFIER 各有具体职责。

可将草案通过 artifact.create_production_document 保存为制作文档并由当前工具回读。没有文件写入与安装工具时不能声称已经注册新 Skill，更不能通过改项目 JSON 假装改了运行方法。

## 验证与迭代

验证文件可读、引用存在、角色与阶段映射正确，未选择的资料不进入请求。用真实类型的输入检查生成结果、可执行工具与用户目标是否匹配，而不是只检查标题或关键词。

修正已观察到的问题，不为想象中的风险增加审批和固定轮次。方法描述为创作建议；只有确实存在的技术限制写成要求。
