# 产品界面与交互动效：专业方法

## 产品视觉与事实

从真实截图、录屏、标志和用户明确要求提取背景、主色、字体、信息密度和控件层级。参考作品只借用运动节奏、缓动或转场，不把它的品牌颜色和文字复制进本片。

清楚区分真实操作演示与生成式概念演示。证明功能时优先现有录屏和可用产品操作能力；生成视频可以表达视觉概念，不能证明软件实际执行成功。用户只给截图时，不声称已完成交互录制。

## 交互因果与运镜

围绕一个真实用户动作建立连续过程：可见输入或光标动作 → 主界面响应 → 内容或空间关系变化 → 相机跟随 → 稳定可读的结果。每次放大都有新的重点，信息不变化时允许镜头保持稳定。

用卡片边缘、路径、图标或共享控件连接前后画面。共享元素扩展需保留对象身份；路径延续需交代方向；遮挡转场需有实际遮挡物；不要用页切换或炫酷运镜几个词代替过程。

## 节奏与可读性

让观众先看见输入，再看运行过程与输出。耗时步骤可以快进，但保留因果顺序和关键变化。每个关键状态留足阅读时间；光标运动、点击与高亮应指向同一操作。

缓入缓出、弹簧、视差和空间穿越服从产品气质与信息层级。不是每个镜头都需要特写，导出等明确动作可以一次点击直接展示结果。准确 UI 文字用原录屏或确定性图版，避免模型重画密集文本。

## 素材与视频编译

截图可以承担布局或视觉参考，是否成为首帧由当前镜头路线决定。给每张图标明页面、区域、用途与时间窗；概念运动不擅自改变实际界面布局和功能名称。

长演示可以按功能和用户动作剪辑成组，不固定每段接尾帧。确需连续穿越的运动才取真实生成尾帧作为下一组输入。视频 Prompt 描述完整的动作与落稳状态，遵守当前 API 字符及媒体限制，不设最低字数或固定切镜数量。

## 验证与交付

查看正常速度播放、关键交互和最终导出。核对真实文字、页面层级、点击目标、输入和结果；概念视频的虚构部分不能混为实测功能。背景音乐与提示音在必要时支持操作节奏，不遮住讲述。

只修有问题的裁切、速度、字幕或画面，不重复录制已经可用的内容；用户只要求剪辑时遵守这一范围。
