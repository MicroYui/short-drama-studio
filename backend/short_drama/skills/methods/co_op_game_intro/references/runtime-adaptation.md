## 创意与玩家信息

从当前用户目标、项目风格和已有素材提取玩家昵称、游戏名称、人数及角色对应关系。已提供的信息直接使用；用户交给 Agent 决定的画风、装备和开场事件可以结合游戏主题确定。真实玩家身份或必须出现的昵称缺失且会改变交付时，集中补齐该信息；只制作概念或提示词时，明确尚未指定的部分即可。

把视觉风格落实到渲染媒介、角色比例、穿搭、背景纹理、界面材质、图标和字体，而不是只加一个风格名。人物参考保留脸型轮廓、发型、眼镜、五官比例等身份锚点；按所选媒介重新表现，避免把照片脸直接贴到风格化身体上。用户选择写实风格时可以保留写实质感。

菜单开场的核心是玩家关系与进入游戏的期待。可以设计共同就绪、相互等待、选择装备或一次合作触发，选一个可读的事件主线；用户只要求菜单静图时，交付静图所需设计即可。已给定方案延续其内容，不为方法步骤重新征集选择。

正常失败例：玩家名字正确但所有按钮比角色更抢眼。先确定进入游戏的主动作和视觉焦点，再降低次级设置的对比与装饰，保留玩家的身份区分。

## 菜单素材与身份映射

每位玩家分别关联身份、昵称、位置、装备和颜色标识。把身份图与界面设计参考的职责分开：前者回答“是谁”，后者回答“菜单如何组织”。已有可用图片按当前用途复用；是否另做界面图、人物图或终态图，取决于本次缺少的信息与实际生成输入能力。

界面层级由主要动作、次级菜单和玩家状态构成。主要动作获得最强对比，按钮尺寸能容纳当前语言，间距和图标风格一致；玩家卡能清楚关联到对应人物。留白和阅读路径适配当前画幅，菜单位置、按钮顺序、人物姿势、灯光和颜色可以随项目改变。沿用现有界面时保留已确定的信息关系，新增造型服从当前美术。

色板分别考虑背景、界面主体、文字与功能强调，危险提示色需有明确语义。人物与背景用一致光向和接触阴影连接，避免 UI 遮住表情或关键装备。准确文字可用当前编辑图版或可读素材承载；如果生成文字不可靠，减少非必要信息并保留真正需要的名称，不把模型误写的文字当作可用结果。

正常失败例：换风格后人脸保留了摄影皮肤，身体却成了剪纸。保持同一身份锚点，统一脸部和身体的材质、边缘与光照，再检查昵称与人物有没有串位。

## 导演与事件节拍

以当前界面、角色和用户目标组织“操作—响应—新状态”。写清是哪位玩家触发哪个按钮、角色或装备怎样响应、界面何时显示就绪，随后如何进入游戏。多个玩家同时动作时分配清晰的注意顺序，给关键昵称和状态留出阅读停留。

静图、角色参考和已有菜单设计提供当前构图与身份依据，不构成额外审批步骤。采用的画幅、时长和输入方式服从当前组与真实能力；提示词、图像或视频分别按本次交付范围推进。设计输出写入当前镜头与引用，视频格式交给现有编译器。

正常失败例：点击、装备切换和场景转场挤在同一瞬间。把触发与反馈拆成清楚的先后状态，缩减次要菜单动画，保留已经正确的人物对应关系。

## 修订判断

检查当前范围内玩家身份、昵称、位置、装备、状态和游戏名称是否一致；文字能否阅读，主要动作是否有可见反馈，人物和界面是否使用同一美术语言。只报告实际读到或观察到的问题，静帧结论限于静帧，音效同步依实际音频判断。

文字拥挤可删减次级信息或调整图版；角色串位时修正身份与位置绑定；脸型漂移时沿用正确身份参考并定位受影响片段；风格偏差时修正材质、色彩或光线，不连带改掉正确的游戏事件。达到当前交付目标即可结束；后续视频制作依据已有任务授权推进。

正常失败例：退出按钮的红色比进入按钮更醒目，抢走主动作。降低退出项的面积与对比，保留其危险含义，再检查阅读顺序。

## 视频编译

分别绑定每位玩家的身份参考、昵称及当前设计的位置、体型和装备；UI 参考负责菜单层级、色彩、字体比例与构图，不能替代身份图。按当前用户的风格改写渲染、光线、城市和 UI 材质，同时保留已确定的游戏事件和文字原文。

把选择、加入、装备响应与进入游戏的过程写成可见事件，说明触发和状态变化。玩家人数、性别、左右位置、装备和配色遵从当前设计；源示例中的两名玩家和固定武器不自动套用到新项目。

正常失败例：两位玩家昵称没有交换，但脸和装备串位。逐人写清稳定身份、昵称、位置与装备对应，并减少同一时窗的切换。文字不可读时精简非必要菜单或使用现有准确图版方案，不靠叠加大量禁用词修复。

## 后期判断

检查玩家身份、昵称、位置与装备是否一致，UI 状态变化是否能看懂。重点观察选择到响应的接点、名字可读停留和多人同屏时的视觉区分；按项目选择的风格核对人物与界面融合。

局部文字、颜色、声音反馈和采用区间可先在当前编辑中修正。人物串位或脸型漂移需定位具体区间，必要时用当前身份参考生成该组的新候选。

正常失败例：加入游戏的提示音出现了，但按钮还没有被触发。移动反馈音或调整采用点；已完成的人物镜头可以保留。交付范围是用户要求的提示词、静图或视频，达到该范围即可结束。
