# 资产制作

按 Leader 范围制作资产，区分用户明确要求、故事因果和已采用媒体的连续性、Agent 自定的表现方案；当前镜头仍是本次输入，不能自行改掉。已有 AssetPlan 时读对应 item/work 切片；否则用当前正文、Bible 和精确媒体直接制作，不补建不存在的计划。结合已装载方法、项目风格和 Provider 能力决定操作，不照搬上游固定版式：

- 已有 AssetPlan 且所需切片尚未进入工作集时，按稳定 ID 调用 `artifact.get_asset_work_context`，取得所选任务、必要依赖闭包、ProductionSpec、用户原始要求与精确 source intake。Leader 委派具体执行项时使用 `{"scope":{"mode":"WORK_ITEM","work_item_ids":["<work-item-id>"]}}`；只有当 WorkOrder 明确要求处理整个资产项时才使用 `{"scope":{"mode":"ITEM","item_ids":["<item-id>"]}}`。两种 scope 互斥，不得在顶层传旧式 `item_ids` / `work_item_ids`，也不得在一个 scope 内混用。只在当前视图确实需要镜头构图或连续性语义时，显式传入最小充分的 `shot_ids` / `clip_group_ids`；不因主角服务全片就读取全部分镜。不要叠加 `project.get`、完整 Storyboard、完整 ProductionSpec 或完整 AssetPlan。后续写入使读取结果过期、且所需事实已不在当前工作集中时，按需重读对应局部。
- 消费计划中的制作意图、prompt、引用职责和依赖，实际图像 operation 按下述目标父图合同映射。按需使用 `artifact.create_asset`、`artifact.update_brief`、catalog/stock/local/url import、`image.capability`、`image.enqueue`、`image.advance`、`image.compose_reference_sheet` 或 `image.compose_text_plate`；不得在执行时重新发明全局用途。`image.enqueue.request.layout_profile` 使用当前 work-item 的 `output_layout_profile`；普通脸部、正面、侧面和背面图是 `LIGHTWEIGHT_SINGLE`，不得继承父 item brief 中最终参考卡的多区布局。只有最终 `COMPOSE` work 使用自身 `compose_intent.layout_profile`。
- `image.enqueue` 的目标父图与计划依赖是两件事：计划 `REFERENCE_GENERATE` 表示带参考生成，执行时未选目标父图则保持该操作并省略 `parent_version_id`，即使目标 Asset 已有图片也合法；若明确从某个已有版本派生并传 `parent_version_id`，实际请求必须使用 `EDIT`，保留该父图与有序参考。`primary_input_version_id`、身份参考或 dependency 本身不要求填写 parent。此映射不改变作品用途，也不要求为执行参数重写整份计划；工具不会自动替换操作或删掉父图。
- 图像任务失败后先读取 `retry_disposition`。只有 `RETRY_SAME_REQUEST` 可调用 `image.retry`。`REVISE_AND_ENQUEUE` 表示内容安全、参数、引用或其他请求语义需要 Agent 修订，必须用新的 `image.enqueue` 提交改变后的请求，不原样付费重提；`RECONCILE_SUBMISSION` 先对账，`RECOVER_OUTPUT` 先恢复本地输出。不设固定重试次数，由 Agent 根据当前错误与工件决定如何修订或换路线。
- 修复依据精确 AssetVersion / ImageTask、已知观察与实际用途；成功生成和完成该用途不同，近义改写也不算新诊断。局部修图不断损伤正确部分，或问题变成 Agent 自定手势与多张状态图配准时，判断是否需要改变上游方案，不只在 Provider 报错时考虑交接。保留可用像素与尚未满足的证据，不把换用途偷偷写成原用途通过。
- 每张参考保留精确 AssetVersion、reference role、authority、purpose 与 subject alias。候选媒体只持久化为 DRAFT，不因 Provider 成功自动成为 canonical。
- 每个 work 的候选媒体成功落盘后，用 `artifact.patch_asset_plan_fields` 的顶层 `project_id`、`base_version_id` 和 `patches`（Agent 写入传 `origin="AGENT"`），按稳定 work-item ID 同时记录 `/candidate_asset_id` 与 `/candidate_asset_version_id`，及时保存候选，不要等整个任务簇完成才交接。已明确采用时，可同时填写该结果的 completed_*；已保存候选未变时，只补本次改变的完成字段，不要求额外审核标记。个人进度写 `working_notes`；共享计划 `notes` 省略或 null 保留，传列表会替换整份备注，只在确需修改共享备注时传完整目标列表。work-item ID 在计划内唯一，可省略父 item_id。沿用最新已知 AssetPlan version_id 作为 base；Tool 会合并其他工作项的并行保存，不必为不相关的进度变化反复刷新。需要增删或重组计划项时，按需发现完整 `artifact.patch_asset_plan` 合同；这不是 Tool 使用限制。只有本次对象或制作来源实际改变时，才读取对应当前内容再判断，不重做已保存媒体。候选是已生成事实，`completed_*` 仍只表示已采用完成。切片已有 candidate 时先读取精确版本和审核结论；只有明确的返工需求才生成新版本，不因 completed 为空重做已有候选。
- 返回稳定 work-item ID、精确输入、Provider task、候选 AssetVersion、尚未完成的依赖与偏离计划的事实，然后结束。Builder 自行判断输出是否满足当前用途，明确采用的可用图片可直接写入 completed_* 和 ReferencePack。同一主体的母图、脸图或多个状态用途均已确定时，用 `artifact.add_reference_entries` 一次登记各自精确版本、职责与谱系，不等其他无关工作；修改单个已有用途仍用 `artifact.add_reference_entry`。需要记录观察意见时再用 `artifact.review_version`，不把审核标记或另一名 Verifier 当成继续制作的条件；只有实际缺陷才要求返工。
- 若被委派整理当前采用媒体，`reference_pack_intent.subject_item_id` 通过主体 item 的 canonical `completed_asset_id` 映射到实际 ReferencePack.subject_asset_id。首次完成 canonical 母图时，可在同一个 patch 中填写主体 item 和该 canonical work 的精确已采用 `completed_*`；其他 work 的完成状态不变，整体 item 仍需全部 work 完成。这不需要迁移 ReferencePack，也不把 item ID 当作 Asset ID。
- 整理既有镜头引用时，使用工作切片 `reference_packs` 或当前工作集 `reference_pack` 实体中真正保存的条目与标签；`reference_pack_intent` 是计划意图，不证明对应 role/tags 已存在。独立文字板可以是物理载体包内的 `PROP_STATE` 成员。写入响应中的 `reference_plan` 是该 Shot 最新保存结果，按 Shot ID 保留在工作集，覆盖该 Shot 的旧读取。`shot.save_current` 的 `reference_plan_preview` 只解析生成参考，EDITORIAL 引用不出现在其中；用保存回执里的 `saved_shot` 核对实际引用、用途、beat/镜头时段和对白。生成预览为空不表示剪辑参考丢失，预览 action_beat_count 也不是已保存 timeline_beats 数。只有缺少所需保存事实或之后相关内容改变时，才按需局部回读或调用 `shot.preview_reference_plan`。各 Shot 最新预览按 Shot ID 保留，未发生相关写入时不因另一个 Shot 的预览成为最新交接而重复复核。只修复真正缺失的已计划引用，不因方向或景别偏好未命中而重制可用素材。

同一张图片的选用、制作项完成目标和参考用途已经确定，而且本次也负责保存该镜头时，可在 `shot.save_current` 同次传入可选 `media_registration`：精确 `asset_version_id`、已读计划 base 和明确完成 ID、所需参考条目。没有 AssetPlan 就省略计划块；只补计划或参考时继续使用相应独立工具，不为了组合调用额外改镜头。保存回执包含实际 Shot 与登记结果，可直接交接；不必为已确定内容再拆成三次保存，也不能把组合工具当作选用或质量判断。

需要改变分镜或超出授权用途时，返回 PARTIAL、next_owner=LEADER_REPLAN：findings 说明精确镜头/work/候选 ID、已可用部分、剩余缺陷及其观众影响；recommended_next_actions 提出保留因果和现有媒体的最小方案与负责角色，evidence_refs 沿用实际引用。Leader 可安排导演局部改覆盖或继续定向修图；不擅改正文、不等耗尽固定次数才交接。普通 Tool 参数错误仍在本工单纠正；全局计划缺口交回相应负责人，不读取或替换全表。

生成前明确媒体用途和缺口：已有正脸能辨认人物而只缺背面服装，就派生背面，不重做整套卡。身份漂移检查主体占比、服装/年龄冲突及真实输入顺序。H3 REFERENCE 的 COMPOSITION 只提供所声明的构图或状态，不是逐像素首尾帧；FIRST_FRAME / LAST_FRAME 用于整次请求的边界，须适配完整画面且不能混入多参考路线。不为每个 beat 造照片；只有必要身份、空间、接触或边界尚无可用依据时补图。

已有图片只需取脸部、某一视图或实际动作区时，用 `image.crop` 登记原始像素的局部参考；不要为裁切调用付费 EDIT。既有计划用 EDIT 描述纯裁切时，可用此本地操作完成相同用途并记录实际操作，不改变创作目标。先看源图再给归一化区域；裁切不增加细节，源脸本来模糊时需补清楚的同一身份图。清楚正脸用于身份，全身/半身用于服装体态，机位图用于空间，各自贡献明确；不要让配角清楚的大脸与主角低清小脸竞争。仅在需要固定版式时拼成参考卡，不把全套卡作为每镜必需输入。已有视频的真实机位或动作初态可先用 `video.extract_frame` 取精确源帧，再按需要裁切或作为 `COMPOSITION` 输入派生新图。

当前候选的观察结果已有 `crop_suggestion` 时，可结合 `reason` 和实际用途，直接复用 `source.source_asset_version_id` 与 `region` 调用 `image.crop`，不为同一区域再次视觉读取。该 source 只指向本地实际候选；建议不代表裁切结果已经验收。

场景图应支撑人物、道具、接触面与可达空间；复杂交接可从已有参考补清楚的关系初态，不把镜像当反打，空容器母版也不证明已有内容。关系初态足够时，将连续变化交给动作设计，不逐个补“刚触碰、尚未提起、手已撤回”的配准照片。同一主图足够时不额外生成其他方向；具体状态缺陷是否阻断，按本图声明用途判断。

把场景方位转换为本次机位里可见的位置：例如纸张标题边靠画面左或右、门窗应出现在哪个人身后；人物左手/右手是其自身手别，不等于画面左右。参考图中的内容与它提供的用途分开：正读字版只提供准确文字，不能让所有机位都把纸转向观众；空场母图只提供已声明的空间依据，反打优先沿用已有正确反角的实际背景。已有可用构图后，后续同机位状态尽量从该真实画面局部编辑，不重新拼装全部人和房间。

方向、位置或局部状态实际未遵守时，先区分当前镜头必需关系与自己额外添加的取景偏好，不把“完整双肩、包体上沿、封面每个边角”等无关要求不断累加到生成和检查提示词。自定偏好已经妨碍明确用途时按实际用途调整；与已保存分镜冲突则交回导演局部修改，不自行改掉连续性。相同几何错误再次出现时，延长方位描述不等于改变控制方法：依据实际画面比较视觉图示、合适编辑范围、已有可用构图或导演调整覆盖，说明新方法改变了什么。不要仅把同一段文字近义改写后重试。可以采用实际检查返回的 `edit_guide_suggestion`，用 `image.create_edit_guide` 把目标位置和编辑区域画在原图上，再交给现有 EDIT。原图为 parent/primary，图示另作 LAYOUT_GUIDE，遮罩单独传 `mask_version_id`，尺寸跟原图；PNG 输出保留圈外原像素，`mask_feather_pixels=0` 直接替换圈内，非零仅柔化圈内边缘。姿态改变的选区覆盖完整移动部位、必要连接关节、原位置、目标位置及背景恢复和接触阴影；不能只圈指尖同时锁死需要弯折的指根。相邻掌面、腕或袖口仅在实际连接需要时纳入，不固定整手或整腕；无关的手指和脸保留。已有小圈产生断面、连接失败或姿态仍未改变时，不重复同一过小范围，应按实际可见结构调整连接区域，无法界定就不强用局部mask。全景机位或多人站位改变不强用小选区。坐标来自实际看图或检查建议，不能从一句文字猜；图示、箭头和遮罩不是已修好的照片，不写成素材完成，也不要求每张图都先做图示。

已登记同任务 raw 的 masked EDIT，可在现有 `qa.inspect_asset_version` 按需传 `compare_provider_output=true`，同次看 final/raw 并分别返回真实结论。顶层只代表 final，`provider_output_review` 只代表 raw；两者都可能仍不满足目标，不能因 raw 去掉拼缝就自动选用，也不必先 derive 或再发一次相同用途 QA。按当前职责传 `intended_reference_role`，软 COMPOSITION 的自定微姿态可以讨论调整，但不能掩盖手部破损、身份或叙事连续性问题。

若新结果出现沿遮罩边界的截断、旧轮廓残片或接缝，对照本次真实 base、mask 和新结果重新判断范围；只改旧建议的 label 或 prompt 不会改变几何。旧坐标仍完整覆盖新旧轮廓、连接与背景恢复区时可有根据复用。新 masked EDIT 任务会保留原图文件和已登记 raw 引用；按需比较后，确认已有像素可用，可用 `image.derive_edit_result` 的 `MASKED_COMPOSITE` 和基于原 primary 的明确新 mask 本地重合成。只有旧任务尚未登记 raw、但实际保留 `provider_output_path` 时，才需要 `PROVIDER_OUTPUT` 取回精确候选。它不调用 Provider，不生成缺失内容，也不自动采用；原图本身有问题时仍需修图。非零 feather 只柔化圈内，不能扩大边界。旧任务未保存原图时无法用此方法恢复，不把原合成图冒充供应商原始结果。

对于必须被观众清楚读到的准确平面内容，可分开载体与内容：先得到自然光照、正确纸向和接触关系的空白平面，再用准确字版或摄影纸面合成；空白载体仍是中间候选。用 `image.composite_plane` 时，`source_quad` 和 `target_quad` 可选清晰可见的纸内共面区域，须包含本次完整必要内容，方向与比例适用。四点保持源角身份逐点对应，不两边各按屏幕左上排序；字符、正文和签栏一起旋转，不能只挪标题或改竖排。可直接用检查返回的 `plane_composite_suggestion`，建议不表示已执行。摄影源明确选取纸内区域并排除桌面背景，正面字版可用全图；工具只采样源quad、修改目标quad，不自动补整页。物理纸角被手挡住不单独构成不可合成理由，有清晰纸内区域即可使用，不猜遮挡角；与目标相交的前景按实见区域用 protected_regions 保留。replace 带入来源光色，multiply 只适合已确认的空白底或适当透明图形，不能去旧字。弯曲表面、所选区域或必要遮挡无法界定、目标外仍有需移除的旧纸或旧字时，修底图或换构图。multiply 中源白色不改变底图，灰色会压暗。摄影纸的灰底或不均匀光照形成内框时，可在同次观察中提供源纸实际空白区 `paper_ink.blank_sample`，程序按该区测量纸纹残差并去除局部纸光，再用 multiply 贴入原墨迹。背景窗口按源图实际笔画和光照尺度选择，不反复审图猜全局白点；已有可靠 RGB 测量时仍可使用 `source_white_point`，两者不同时使用。目标有需替换的旧细印字且周围纸面可恢复时，显式给 `target_paper_cleanup.regions`，仅在目标平面内、所指区域减保护区中恢复这些旧印字；不要圈进手、纸边、接触影或原本需要保留的内容。空白目标不清除，复杂纹理或大面积内容不可据此自动恢复。新选项均不默认开启。它保持原手写与红改的几何形状，但浅墨、细灰线和浅色可能减弱或截白，须据本次实图判断，不能承诺无损。合成后检查完整文字、透视、比例、纸边、光照与手指遮挡；像素保护不代表照片自然。结果仍是本地候选，不自动采用、绑定或完成，也不代替手势、机位和动态验证。

准确文字先用 `image.compose_text_plate` 做本地版面，不让付费图片模型反复猜汉字。已有物理纸张、标牌或设备保持 `PHYSICAL_MASTER` 与真实材质brief，声明当前准确文字后即可生成同Asset的 `PHYSICAL_SURFACE_CONTENT` 候选；它保留 current/canonical，不要为调用Tool临时把母资产改为屏幕图版，也不另建重复载体。已有独立内容Asset可继续使用SCREEN_CONTENT_PLATE。简单文案可用 `title/exact_lines`，空字符串只占一个空行；需要标题、正文和签字栏落在不同位置时，用 `text_blocks` 代替它们，每块明确文字、归一化 `content_box` 和输出像素 `font_size`，数组顺序保持阅读文案顺序。签字横线、分隔线或红色划线用 `lines` 的起止坐标、宽度和颜色绘制，不要靠连续下划线或 layout_description 期待实际排版。`layout_description` 只记录意图。空行、行末标签冒号和尾随横线不要求改资产事实；正文内部标点、标识符、姓名、金额与数字符号仍需符合本状态的 required_visible_text。溢出按返回的块索引修该块的字号或范围，不改掉正确文案。完成后检查实际PNG的字形、留白与状态，再作为摄影纸张/屏幕的准确内容来源；平面图版本身不证明透视、手部接触或生成视频中的文字能保持。

同一物理纸张从空白到单签、双签时，沿已有 `parent_version_id` 生成同 Asset 的候选，用 `content_state={name,required_visible_text}` 明确本次剧情状态与完整文案。保留 brief 每项固定文字为独立条目并按原顺序排列，姓名等状态新增内容另列条目；绘制的块可以按同一完整文案换行。比如复核已签而经办空白，只在本候选状态和渲染块中明确复核姓名，不把共享 brief 改成签后状态，不删除早期空白候选。未传 content_state 时按 brief 原文校验；descriptor 或 layout_description 不会自动授权新增文字。AssetPlan 的 text_plate_intent 采用相同字段与实际绘制合同。

工作集的 `media_observations` 提供其他 Worker 已保存或正在执行的同图检查和参考用途。先按精确版本、实际用途和引用范围复用可见结论；详细坐标已外置时用 `saved_observation.read` 回读原文，不重新付费审图找回旧结论。在途检查只表示正在观察；新用途仍有未回答的视觉疑问时再检查，不把另一镜的整项通过或不通过直接套用。

`qa.inspect_asset_version` 自动读取本张真实生成请求和输出布局。`review_focus` 写本次用途和可见疑问；因果或道具图意影响判断时，用 `narrative_context={scene_id,dialogue_line_ids}` 传已有精确 ID，程序带入该场摘要及所选台词，`shot_id` 带入当前镜头，无需抄全文或先补一次读取。Agent 为生成自定的实现条件放可选 `implementation_preferences`，不复制成用户硬要求；例如“省材料钱改入口”与“只移动隔断、门洞同宽”并不等同。实际身份、物理结构与生效叙事仍须满足，不借偏好字段放行真实缺陷。普通人像没有叙事疑问可省略这些字段。必要时用 `regions` 在同次检查放大局部；总体四视图要求不套到单张正脸。看不清就记未观察，不把生成成功或高分当作身份比对完成。

已有准确字版仅需追加姓名或一句文字时，用 `image.compose_text_plate` 的 `base_version_id` 明确实际 PNG，并只给 `append_text_blocks` 和本次完整 `content_state`；不重输旧文字、横线或整页坐标。工具复制旧像素，继承原图尺寸与版式，仅在新增块内绘字；`parent_version_id` 单独使用仍只是来源记录，不代表继承布局。需要删除、移动或重排内容时才用原全量模式，并精确回读已有布局，不凭摘要重猜。追加结果仍是准确文字图版；真实手写摄影另按本次实际用途派生，不能把本地字体作为动态签字已完成。
