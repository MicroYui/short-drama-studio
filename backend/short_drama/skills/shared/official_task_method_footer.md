# 本地执行优先级

上游原文提供成熟的制片经验，但必须在当前项目的用户意图、`ProjectDocument`、版本化工件、`DurationContract` 和 Provider Capability 内语义化使用。用户明确的选择和当前结构化契约高于上游默认流程。

上游中的创作数值和步骤数量——包括节奏百分比、固定段数、题材或方案数、爽点次数、全局语速上限、默认问询轮次、审校或重试次数——只是可选发想起点，不是配额、代码门禁、必修理由或自动停机条件。Agent 根据实际文本、表演、资产和生成证据做当前决定，并允许合并、省略、重排或选择更合适的数值。

只有已接入 Provider 的真实技术边界（例如 H3 单个生成组的 4–15 秒能力）、媒体本身的时间轴事实和当前有效引用的一致性才是硬边界。上游默认确认点、Gate 或 fallback 顺序必须转译为 Leader 对当前语义和证据的自主判断；不得使用关键词、正则、固定次数或额外审批门代替这个判断。

本地协作补充：不继承上游的冻结、预算配额或强制验收顺序，不以“必须另一名 Agent 批准”阻止制作。负责人可委派制作兼自查，检查结果提供具体观察即可；历史 APPROVED 字段表示当前采用，不意味着每份内容需要额外人审。用户明确要审阅文本修改时才提交 change.propose_text，并等待该提案的实际选择。

核心资产按项目实际需要准备完整覆盖。用户只给单张人物或核心场景参考时，可以先生成可复用的多视图再进入镜头制作；人物完整四视图使用 CHARACTER_FOUR_VIEW_4X1（正面、左侧、背面、右侧），场景使用 SCENE_FOUR_DIRECTION_2X2。直接把真实原图作为 EDIT 的身份或空间参考，检查四个方向是否齐全和一致；可用整图直接采用，不为旧双区模板强求额外布局 guide。已有四视图直接复用。后续镜头正文 @ 绑定实际选定的这份媒体。

分镜执行采用当前工具语义：begin_storyboard_draft 后可以直接逐组写入，再 finalize。旧文档中的时间账本、sealed outline、时长预算和独立 Verifier 都是可选方法，不是唯一编译路径。实际镜头内容与用户最新要求可以改变规划；只在写入时检查实际来源、身份和时长合计。
