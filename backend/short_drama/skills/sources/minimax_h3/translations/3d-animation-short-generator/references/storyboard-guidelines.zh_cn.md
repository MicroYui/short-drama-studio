# 文本分镜与铅笔分镜指南

## 步骤 6：文本分镜文档（默认）+ 铅笔分镜图（可选）

步骤 5.5 自检通过后，在生成任何分镜工件之前，展示分镜模式选择卡：

- **仅文本分镜文档（默认、推荐）**——一个包含所有镜头分镜的画布文本节点，各镜头以文档内章节的形式组织。沿用半旁白剧情分镜结构：逐镜头字段（标题 / 钩子 / 场景 / 角色 / 空间锚点 / 连续性 / 表演），再加上皮克斯式的每画格四象限内容和可选 ASCII 布局。以接近零成本承载完整的质量控制信息。步骤 7 中选择的视频模型会直接读取该文档，将其作为逐镜头渲染参考。
- **文本分镜文档 + 多画格铅笔图（可视化模式，可选）**——仍然生成文本分镜文档，并将其作为权威工件；此外为每个镜头生成一张多画格铅笔图，供人工审核。成本更高，适用于用户希望在投入视频生成前查看视觉预览，或者挤压与拉伸/姿势剪影是主要风险、用户希望提前进行视觉检查的情况。

将选定的分镜模式存储在 Project Brief 中，并在步骤 7、步骤 9 和重新生成纪律中复用。

### 默认路径：单一文本分镜文档

生成一个名为 `<title> text storyboards` 的画布文本节点（整部短片使用一个文档）。即使还生成了铅笔图，该文档仍是步骤 7 的权威渲染参考。其结构沿用半旁白剧情分镜——每个镜头都是同一文档中的一个章节，因此用户无需在节点之间跳转即可阅读跨镜头连续性。

文档前置内容（位于文档顶部的页眉区块）：

- 项目标题、获批的视频模型、获批的分辨率、分镜模式和自检状态（例如 `shot-table self-check: passed at <timestamp>`）。
- 一份简短的目录，列出每个镜头、其钩子和章节锚点（`S01`、`S02`……），便于用户跳转。

逐镜头章节结构（按照镜头顺序，每个镜头使用一个 `##` 标题）。每个章节都必须按照以下顺序包含这些字段——直接改编自半旁白剧情分镜：

1. **Shot title & duration**——简短易读的镜头标题，加上 `S<N> / <duration>s`（例如 `S03 / 6s`）。
2. **Hook type**——从受控词表中选择一个：`setup` / `visual-joke` / `reversal` / `reveal` / `callback` / `suspense` / `tender` / `chase` / `expression-beat` / `climax`。用于单集钩子分布自检。
3. **Scene & characters**——场景卡的准确名称和画内角色的准确名称（绑定角色卡）。
4. **Spatial anchor card**（必需，包含四个子字段——直接改编自半旁白剧情分镜）：
   - `Fixed landmarks`——命名地标及其相对于画面的位置（例如 `door-frame: right third`、`kitchen-island: center bottom`）。
   - `Character positions (camera view)`——每个画内角色相对于画面的位置、面向方向和初始姿势。
   - `Exited character status`——上一镜头中在场、但本镜头中不在场的角色，以及他们的画外位置和原因。
   - `Lighting baseline`——继承自场景卡的主光/补光/轮廓光方向，以及逐镜头调整。
5. **Continuity**（沿用半旁白剧情分镜的交接字段）：
   - `Continuity from S(N-1)`——用一到两句话引用上一镜头的结束状态。
   - `Continuity to S(N+1)`——用一句话为下一镜头的开场做铺垫。
6. **Double-binding**——`[char:角色名-01] [char:角色名-02] ... [scene:场景名] [hook: visual-joke]`——角色卡的准确名称、场景卡名称和钩子类型。这些是仅用于分镜的参考标记；视频模型会在渲染时将其移除。
7. **Per-panel four-quadrant content**（每个画格一个区块，按时间顺序排列；这是皮克斯式逐秒指令，逐字沿用表格行中的内容）：
   - `Timecode`——例如 `0–1s`。
   - `Pose + Expression`——具体的身体姿态、剪影、关键道具握持方式、视线、面部表情变化路径；对于弹性动作节拍，明确指出挤压 / 拉伸 / 预备动作 / 过冲。这是每个画格中最大的部分，也是视频模型读取的视觉节拍。
   - `Camera`——景别、摄影机运动（推 / 拉 / 摇 / 俯仰 / 手持抖动 / 固定 / 环绕），以及适用时的荷兰角备注。
   - `Audio + Anchor`——音频提示（`♪ narration: ...` / `dialogue: ...` / `SFX: ...` / `silent`）和空间锚点备注（`door-frame: right third` / `Mia: center midground facing camera`）。
   - 表演备注（沿用半旁白剧情分镜）：旁白出现的秒数标记 `narrator-mouth-closed: true`；画内对白标记 `mouth-open: speaker`，并描述表情变化路径 / 视线 / 身体动作变化。
8. **Layout rules**（逐镜头应用）：
   - 3 秒镜头 → 3 个画格（每秒 1 格）。
   - 4 秒镜头 → 4 个画格。
   - 5 秒镜头 → 5 个画格。
   - 6 秒镜头 → 6 个画格。
   - 7 秒及以上镜头 → 每秒一个画格；对于关键的亚秒级节拍，只有当该节拍是镜头钩子时，才额外添加一个类似 `2.0–2.5s` 的迷你画格。
   - 画格必须无时间空档地覆盖镜头从首帧到末帧的全部时长。
9. **Per-panel binding**：
   - 绑定表格行中列出的准确角色卡，以锁定外观、面孔、发型、身体比例、服装、标志性道具和角色身份。使用与表格相同的角色名称。
   - 绑定该行中列出的准确场景卡，以保持环境、道具、地标、移动路径和空间逻辑。
10. **Optional ASCII layout block (highly recommended, free)**：
    - 为每个画格附上一张小型 ASCII 草图（或为整个镜头附上一张组合草图），让用户无需渲染图片即可在几秒内浏览空间布局。示例：
      ```
      [0-1s]  Mia (L, mid)         door-frame (R)
              ──kneels, hands on apple basket──
              cam: low push-in, locked
              audio: silent | anchor: basket center-bottom
      [1-2s]  ...
      ```
    - ASCII 区块仅供参考；视频模型读取的是上方结构化的 `Per-panel four-quadrant content`，而不是 ASCII。
11. **Storyboard-only markers**：
    - 当某个节拍至关重要时，在画格时间码后附加 `[BEAT]`。
    - 当某个画格必须向下一画格或下一镜头交接特定状态时，附加 `[HANDOFF → ...]`，并使用类似 `[HANDOFF → S04 opening]` 的简短标签。

逐镜头章节模板（可复制粘贴的骨架，适用于任何镜头）：

```markdown
## S03 / 6s — Title: 奶奶把苹果筐递给 Mia

- **Hook type**: reveal
- **Scene & characters**: scene:kitchen | char:Mia, char:Grandma
- **Spatial anchor card**:
  - Fixed landmarks: door-frame (right third), kitchen-island (center bottom)
  - Character positions: Mia (L, midground, facing camera) | Grandma (R, foreground, facing Mia)
  - Exited character status: —
  - Lighting baseline: warm overhead key + cool bounce right
- **Continuity from S02**: 奶奶弯下腰从中岛拿起苹果筐
- **Continuity to S04**: Mia 接住筐转身，门铃响起
- **Double-binding**: [char:Mia] [char:Grandma] [scene:kitchen] [hook:reveal]

### Per-panel four-quadrant content

#### 0–1s
- Pose + Expression: 奶奶弯腰双手持筐；Mia 左侧站姿，眼神好奇
- Camera: locked medium shot, eye-level
- Audio + Anchor: silent | Mia: L midground | basket: center bottom
- Performance: [BEAT]

#### 1–2s
- Pose + Expression: 奶奶手臂伸向 Mia，筐倾斜；Mia 双手前伸准备接
- Camera: locked medium shot, eye-level
- Audio + Anchor: ♪ SFX: basket rustle | anchor: door-frame: right third
- Performance: [HANDOFF → S04 opening]

#### 2–3s
...

### ASCII layout (optional)
[0-1s]  Grandma (R, fg)        door-frame (R, bg)
        ──lifts basket──        Mia (L, mid)
        cam: locked | silent
[1-2s]  ...
```

所有章节写完后，将文档放置到画布上并直接进入步骤 7。默认模式下不要调用任何图像生成模型。

### 镜头级提取（高频迭代模式）

默认的单一文档形式针对阅读和跨镜头连续性进行了优化。当用户标记某个特定镜头需要高频迭代时（通常是高潮 / 追逐 / 肢体喜剧节拍，其每画格内容需要多轮修改），将该章节提取为独立文本节点，使迭代集中在局部：

- 用户信号：步骤 6 之后的任何时间，用户提出“让我专注处理 S05”“S05 需要重做”“提取 S05”，或在分镜批准选择卡中选中某个镜头。
- 提取机制：
  1. 创建一个名为 `<title> S05 text storyboard (extracted)` 的新画布文本节点。
  2. 将 `## S05` 章节的完整内容从文档移入新节点。
  3. 在文档中，用一行占位符替换 `## S05` 章节：`> S05 — extracted to standalone node (see `<title> S05 text storyboard (extracted)`)`。
  4. 步骤 7 从提取后的节点读取 S05；其他所有镜头仍从文档读取。
- 重新整合：用户满意后，将独立节点折叠回文档（用最新内容替换占位符），并归档独立节点。
- 提取多个镜头：每个镜头各自拥有一个独立节点；文档通过占位符跟踪它们。

提取机制之所以存在，是因为独立节点最适合按需使用，而不应默认使用——但当某个特定镜头承受较高迭代压力时，独立节点始终可用。

### 可选路径：多画格铅笔分镜图（可视化模式）

如果用户在分镜模式选择卡中选择了可视化模式，除了文本分镜文档外，还要为表格中的每一行生成一张多画格铅笔分镜图。文本分镜文档仍然是权威渲染参考；铅笔图仅供人工审核。

对于每张铅笔分镜图：

- **双重绑定标签（图片右上角，必需）**：
  - `[char:角色名-01] [char:角色名-02] ...`——本行使用的角色卡准确名称。
  - `[scene:场景名]`——场景卡的准确名称。
  - `[shot: S03] [dur: 6s] [hook: visual-joke]`——镜头 ID、时长和钩子类型。
  - 这些标签是仅用于分镜的参考标记；它们会在视频渲染时被移除。
- 绑定该行列出的准确角色卡，以锁定角色外观、面孔、发型、身体比例、服装、标志性道具和角色身份。
- 绑定该行列出的准确场景卡，以保持环境、道具、地标、移动路径和空间逻辑。
- 将该行的每条逐秒指令转换为一个分镜画格或一个标记清晰的节拍画格；4 秒镜头通常创建 4 格；6 秒镜头通常创建 6 格；只有在必要时才为关键的亚秒级节拍添加额外迷你画格。
- **画格物理布局（必需）**：
  - 3 秒镜头 → 1×3 条带。
  - 4 秒镜头 → 2×2 网格。
  - 5 秒镜头 → 上排 3 格 + 下排 2 格。
  - 6 秒镜头 → 2×3 网格。
  - 7 秒及以上镜头 → 3 排，画格均衡分布。
  - 每个画格占据相同的画布面积；不要让某一格占据主导。
- **每画格四象限内容（必需）**：
  - 左上：时间码（例如 `0–1s`）。
  - 右上：姿势 + 表情草图（面积最大；实际视觉节拍）。
  - 左下：摄影机图标 + 运动箭头（推/拉/摇/环绕/固定），以及一条很小的荷兰角备注。
  - 右下：音频提示（例如 `♪ narration: "I knew it."` / `SFX: door creak` / `silent`）和锚点备注（例如 `door-frame: right third`）。
- 按阅读顺序将画格排列在同一张单镜头分镜图中；不要把多个不同镜头合并到一张图片中。
- 每个画格必须标记时间码，例如 `0–1s`、`1–2s`，并展示对应的姿势、表情、动作、摄影机运动、道具位置、音效提示和连续性交接。
- 仅输出纯黑白铅笔线稿：不得有颜色、最终渲染光照或精致的 3D 渲染。
- 在分镜图上标记镜头编号，并在有用时为每个画格加入摄影机运动图标/标记。
- 在有用时加入仅用于分镜的标记：铅笔结构线、动作箭头、摄影机路径图标、时间标记和简短备注。
- 只将草稿用作视频渲染参考资产，而非最终美术。

### 分镜批准（两种模式）

生成全部文本分镜章节（以及可视化模式下的铅笔图）后，按镜头顺序将它们放置在画布上，并分组为：
- `<title> text storyboards`（默认模式，单一文档），或
- `<title> text storyboards + multi-panel pencil storyboards`（可视化模式，将文本文档与铅笔图分别分组，因为铅笔图包含文本文档中没有的双重绑定标签、ASCII 标签和镜头编号）。

向用户展示选择卡：

- 批准分镜并渲染镜头视频（推荐）
- 提取 / 重新整合某个镜头（在文档与独立节点之间移动章节）
- 重画选中的铅笔分镜（可视化模式）
- 修复角色一致性
- 修复场景逻辑
- 修复摄影机标记
- 修复音频/锚点标记

### 分镜生成失败回退（仅限可视化模式）

如果无法生成达到所需质量的铅笔分镜图（例如布局崩坏、标签难以辨认、画格合并、角色不一致），请先按以下方案逐级处理，再询问用户：

1. **第一次重试**：重新生成同一镜头的分镜，并收紧提示词，明确提及四象限布局、`[char:…] [scene:…] [shot:…]` 标签以及每个画格的内容规则。
2. **第二次重试**：移除右下角音频/锚点象限中的文字（将其保留为空白单元格，只放置一个很小的 `♪` 标记），以降低文字负载；这种做法通常能在不损失视觉节拍的情况下修复难以辨认的标签。
3. **第三次重试**：减少一个画格（例如将最不具可执行性的两秒合并，把 6 格改为 5 格），并将摄影机图标简化为单一箭头。
4. **同一镜头连续三次尝试失败后**：暂停并向用户展示选择卡：
   - 仅为失败镜头切换到色块分镜（用灰色方框表示姿势，不使用铅笔线条）。
   - 移除失败镜头的铅笔图，仅依赖文本分镜文档中对应的那一行。
   - 在步骤 5 中把失败镜头拆成两个更短的镜头，并重新执行步骤 5.5。
   - 手动提供一张参考图片进行绑定，而不是生成图片。

在默认文本模式下完全不需要这套回退方案——只有当模型无法生成连贯的结构化文本时，文本分镜才会失败；此时应返回步骤 5 修改表格行。
