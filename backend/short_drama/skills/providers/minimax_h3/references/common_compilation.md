# H3 通用编译方法

## 第一步：先冻结要翻译的事实边界

编译前先从输入中列出不可改变的事实：镜头作用、可见人物、服装、场景、道具状态、左右手、人物位置、视线、动作顺序、对白、声音来源、时长、画幅和已选路线。只要其中一项仍互相矛盾，就不应靠 Prompt 修辞掩盖，应把问题返回给导演、资产或路线规划层。

visible_assets 是本镜头可见资产的权威清单。对白提到某人，不代表此人必须入画；上一镜出现某个道具，也不代表本镜可以自动继承。`previous_shot_terminal_state` 只说明本镜如何承接物理终态，不能扩张当前镜头内容。

structured_action_plan 是导演 Agent 为当前镜头声明的动作顺序和物理交互关系。它用于把已批准动作编译得更精确，不授权 Prompt Compiler 新增动作、改变接触关系或重写镜头。

## 第二步：把镜头还原成可观察的时间线

按播放顺序组织，而不是堆叠标签：

1. 开始时画面里已经有什么，人物和道具在哪里，身体与表情处于什么状态；
2. 哪个主体先行动，动作作用于谁或什么，接触发生在哪里；
3. 状态怎样连续变化，哪些东西必须保持不变；
4. 摄影机何时、以什么方向和速度运动，运动服务什么信息；
5. 对白、环境声、动作声和音乐在什么时刻出现，声音来自画内还是画外；
6. 最终帧的人物位置、姿态、持物、表情、构图和可继续剪辑的状态。

动作必须来自 `locked_shot`、`source_prompt` 或 `structured_action_plan`。不要为了让提示词丰富而增加转身、走动、拥抱、递物、出入画等未声明动作。复杂接触关系使用明确的施力者、作用部位、目标表面、开始状态和结束状态；`contact_persists=true` 时，接触需保持到最终帧或后续动作明确解除。

## 第三步：写可执行的摄影机语言

摄影机描述至少说明运动类型，必要时再补充方向、幅度和速度，例如缓慢前推、轻微手持跟随、从右向左平移。摄影机变化应与主体行动和叙事注意点同步，不使用“高级、大片感、震撼”等无法执行的形容词代替空间关系。

单镜 `ShotPlan` 默认只产生 `[Shot 1]`。只有锁定镜头本身已经明确包含多镜覆盖时，才允许新增后续 Shot 段，并使用严格递增的精确时间，例如 `[Shot 2] At 00:03.500`。编译器不能为了解决信息过载自行拆镜；应把拆镜建议返回导演层。

GenerationUnit 调用以 `locked_shots` 中的有序编辑镜头为准：每条 `required_timing_marker` 原样置于对应自然叙事段落开头，台词留在其原始段落，不把全部台词移到声音汇总中。组内 beat 时间先加该镜 source window 的起点，再用于整个片段。一次 Provider 生成多个编辑镜头不会抹掉这些镜头的裁切边界。

## 第四步：处理对白与声音来源

- 同一镜头内为说话人使用稳定编号，如 `(S1)`、`(S2)`。
- 对白逐字保留，写为 `<d>[Chinese] 原文</d>`；不得压缩、润色或翻译。
- 画外音使用明确的 `says in an off-screen voiceover`，并说明画面人物嘴唇保持闭合。
- 画内对白应与人物身份、表情、口型和表演节拍对应。
- 环境声、动作声和对话属于 `overall_soundscape`；非叙事音乐单独进入 `non_diegetic_music`。
- 不需要音乐时明确写 `N/A`，不要为了填字段而添加音乐。

禁止自动生成字幕、水印、标识或其他可读文字。只有锁定事实要求画面文字时，才原样保留并说明其位置与用途。

## 第五步：控制节奏和连续性

根据镜头目的、总时长和已声明动作安排节奏，不套用固定动作数量或固定秒数模板。没有“越多动作越好”；重要的是开场可识别、动作关系清楚、结束状态可接下一镜。

除非镜头明确要求瞬间开始或压尾结束，给起点和终点保留自然的可读时间。不得用瞬移、突然换手、道具消失、角色换脸、无动机越轴或光线跳变来压缩动作。

## 第六步：提交前自检

逐项核对：

- 路线没有被编译器改换；
- 字段名和顺序与 `required_prompt_schema` 相同；
- 时长和画幅明确；
- 锁定对白逐字存在，声音来源正确；
- 人物、服装、道具和场景没有新增或串镜；
- 开始、发展、结束状态连续；
- 媒体标签与实际请求绑定完全一致；
- 没有 Markdown、解释性前后缀或多套候选 Prompt。
