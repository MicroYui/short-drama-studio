# AI 原生短剧

## 成片目标

面向抖音等短视频平台的连续观看场景，用生成式图像、视频和声音完成可连载的短剧。作品应当开篇即可理解、观看承诺明确，并持续通过可见行动、信息变化、关系变化和情绪回报推进；每个镜头还应当能够被单独生成、检查、替换和重新剪辑。

“AI 短剧”描述的是内容消费形式和生成式生产方法，不是 anime 的同义词，也不等于传统真人实拍微短剧。它可以采用 AI 仿真人或写实生成角色、二维/三维动画、动态漫/有限动画、真人主演加 AI 的混合制作，或这些形态的组合。保留用户给定的题材、语言、人物、时代、地域和视觉选择，不得用通用网感套路覆盖项目自己的辨识度。

## 格式层边界

本 Skill 只说明 AI 原生短剧的消费场景、可读性、视听密度、竖屏与生成式制作特点。它是宽粒度 `ProductionProfile`，不定义爽剧、悬疑、喜剧、爱情或其他题材类型。

- 用户明确要求与禁区属于 `StorySourceContract`。
- `SCRIPT_LOCKED` 普通文本中的锁定台词由 Story Orientation Agent 按完整语义整理进 `StorySourceContract.locked_dialogue`，也允许调用方直接提供结构化条目；格式 Skill 不用正则、冒号模板或说话人关键词替代语义判断。
- 目标观众体验、戏剧引擎、推进策略和调性/可信度属于 `StoryIntent`。
- 本集回报、闭合线索、最后画面/台词与续集策略属于 `EndingContract`。
- 视觉、摄影、材质、色彩、声音等属于 `ProjectBible.style`，不代替叙事意图。
- 爽感放大、递进兑现、荒诞喜剧等方法由 Story Orientation Agent 根据整段项目语义选择可组合 Narrative Skills，不由代码做关键词路由。

共享 Story Architect 只负责故事承诺、人物选择、因果推进和结尾意图；四视图、场景 coverage、时间线分镜以及 H3 `@` 媒体绑定分别由剧本之后的资产、导演和 Provider 层处理，不应反向污染故事架构 Prompt。

## 视觉形态边界

- AI 仿真人、二维/三维、动态漫、真人与 AI 混合都是可选表达，不构成封闭分类；Agent 也可以形成适合当前作品的其他风格或组合。
- 视觉形态由用户要求、来源素材和项目 Bible 的 `style` 自由描述。Agent 可以给出创意建议，但不得因为某条路线更容易生成就静默改成 anime、仿真人或其他媒介。
- 资产和成片检查只判断是否符合本项目已声明的 Style 与镜头职责，不预先要求某种人物质感、脸型、材质、运动量或摄影语法。
- 当产品目标是动画视觉语言本身，而不是连续 AI 短剧时，才使用独立 `ANIME` Skill；短剧采用动画画面时仍可由本 Skill 统筹其连续叙事与 AI 生产。

各形态的选择、资产、镜头、声音和审核方法见 `references/ai_native_forms.md`。

## 内容原则

- 短视频的冷启动观众缺少前情，开场应尽快让当前人物、情境、主动问题与观看承诺可读，不用与后文无关的噱头骗取注意。
- 减少与当前承诺无关的铺垫，但保留理解人物正在做什么、为什么这样做以及结果是什么所需的最小信息。这个最小因果密度应根据项目声明的调性调整，不默认为审计式现实主义。
- 信息密度可由行动、反应、旁白/对白、声音、画面线索和剪辑共同承担，不把每句文本压成口号。
- 节奏同时存在于叙事信息、表演/画面动作、剪辑和声音；快节奏不等于持续快说、快切和加大音效，慢段也应承担可读的等待、发现、压力或情绪。
- AI 短剧不默认要求爽点、爆点、打脸、反转、悬疑或荒诞。具体叙事体验由 `StoryIntent` 与 Agent 语义选择的 Narrative Skills 决定；`ProjectBible.style` 只负责对应的视听表达，格式 Skill 不把某种爆款模板套给所有作品。
- 每一段和每一集都要完成它在当前作品中的叙事或情绪职责。是否保留续集动力由 Story Architect 根据用户意图与完整上下文判断，不用关键词正则或固定句式代替创作决策。
- 场次数和需要联动修订的场次范围由当前故事与实际问题决定，不设置 40 场、跨场 12 场等固定配额；多分钟任务通过蓝图、逐场稿件和修订单元持续保存进度。

## 人物、文本与表演

- 根据形态决定叙事骨架由角色对白、旁白、内心音、画面文字或混合方式承担；不要把动态漫强行写成全程口型对白，也不要把仿真人场景退化成配图朗读。
- 中文角色对白优先口语自然、可朗读、可呼吸、可打断；旁白优先清楚推进因果，并为画面保留证明和补充空间。
- 能通过动作、目光、姿势、构图、道具状态、环境变化或反应表达的内容，不重复写成说明文本。
- 快节奏不等于人物始终快速说话或画面始终大幅运动。迟疑、静帧、停顿和长反应可以成立，但必须承载选择、悬念、尴尬、威胁或发现。

## 竖屏视听原则

- 核心人物、关键动作、道具状态和情绪反应要在小屏幕上第一眼可读。
- 多人物画面要主动管理前后景、轮廓、遮挡、视线与银幕方向，不能把横屏构图简单裁成 9:16。
- 字幕、旁白文字、界面和图形不能遮挡嘴部、表情、动作轮廓或关键道具；画面重要信息应处于平台界面的安全可读区域。
- 镜头运动、转场、音效和音乐都应服务于信息或情绪变化。没有变化目的的持续晃动、推拉和快切只会降低可读性。

## 剧本完成后的制作衔接

- AI 短剧常需跨镜、跨场复用角色与场景，但连续性精度仍由当前剧情职责、屏幕可见性和复用范围决定，不默认为每个角色与场景都准备最重资产包。
- 竖屏小屏中的身份、关键动作、表情和道具状态应保持可读；一个镜头或资产无法同时承担多个冲突职责时，由下游 Agent 拆分覆盖。
- 具体四视图/群像轻量资产、场景 coverage、关键帧、H3 路线和媒体绑定方法以共享 workflow、资产/导演角色和 Provider Skill 为准，不在本格式 Skill 重复定义。
- 生成后必须观察实际视频，再将故事、镜头、资产、输入、运动、声音和剪辑问题交给各自责任层。

## Agent 行为边界

- 先读取当前 ProjectDocument、锁定内容和已批准工件，再提出改动。
- 对局部修改使用依赖影响分析，只重做受影响的资产、镜头、Take 和时间线边界。
- 把固定秒数、固定反转数、固定镜头数、固定对白密度视为可测试假设，而不是平台硬规则。
- 不把某份示例 Prompt 中的“15 秒/13 切”、AAA 游戏角色片、固定字卡、固定配色或全程激进剪辑当作 AI 短剧风格；只提取主体锁定、时间分段、媒体职责和声画同步等可迁移方法。
- 只有 Critic 或 Verifier 留下需要脱离大纲辩护再通读的具体疑点时，才让冷读角色检查完整剧本、最后一场和最后一句；无此疑点时可直接收尾。Production Manager 执行这个 Agent 语义决定，不把最终冷读设为必经门禁。
- 专业 Agent 若需调用 Tool，沿用共享 Harness 的 `specialist_turns` 单步持久化：一次外部执行只做模型决策或一个 Tool 动作，重启后交回 Agent 判断是否对账或重试；本格式 Skill 不规定调用次数。
- 若存在真实平台数据，把分段观看、续看、重播、评论语义、收藏、分享和下一集进入作为组合诊断信号；没有数据时只输出观看风险预判，不伪造留存结论。
- 用户可以覆盖本 Skill 的建议；Agent 应说明取舍及其对内容、连续性或交付的影响，不增加审批门。

## 验证状态

当前已有文件化格式 Skill、中文共享角色、可组合 Narrative Skills 及其运行时编译路径。这不等于已证明某种叙事 Skill 选择、审校强度或资产覆盖策略能在所有题材上产生好成片；这些结论需通过真实语言模型剧本、真实资产与完整播放继续验证。
