## 1. 用户反馈与实际缺口

用户指出镜头里没有 `@图片` 一类引用，看不到在何处使用什么资产，也看不到文案与资产的绑定。上一版只有镜头级资产清单和详情入口，不能表达某一句动作、某个时段到底参考了哪张图及取用什么内容。需要补齐的是内容关系及可编辑交互。

当前代码与真实记录分别是：

- `ShotTimelineBeat.references` 已支持 `ShotReferenceCue`，包含 `subject_asset_id`、`alias`、`required_tags` 和 `purpose`，用于某一时间段的语义参考。真实开场三镜的六个 beat 中，这一数组均为空，不能宣称已有完整正文引用绑定。
- `H3MediaInput` 已保存具体 `asset_version_id`、`subject_asset_id`、`reference_alias`、`binding_purpose` 与 `reference_tags`。内部文件编号可复用，不给用户增加版本管理界面。
- `resolve_h3_media_bindings` 根据有序媒体输入产生 `<Picture N>` / `<Video N>` / `<Audio N>`，并把同一主体的图片映射到 `<Subject N>`。`@别名` 不是随便打在文字前的装饰。
- 本案例开场实际请求使用六张图片：林一身份图、刘阿姨身份图、食堂四向卡、价牌载体、红烧肉文字层、青菜文字层；后三张属于同一个价牌主体。因此六张输入图与四个主体不是一一对应。

## 2. 用户看到什么

镜头默认呈现完整、易读的分镜文字。人物、场景或具体参考在适用位置呈现带小缩略图的 `@` 引用，例如：

> 拍摄环境：在 @学校食堂 的打饭窗口，@林一 位于窗外，@刘阿姨 位于窗内。
>
> [1.8–4.0 秒 · 本镜头内] @林一 平静报出“十四元”，镜头随后移焦到 @刘阿姨 停在饭卡机前的手。

用户进一步明确要求鼠标移上去即可看到图片预览。**悬停正文或资产条中的引用，直接显示该处实际绑定的图片、具体资料名称、取用用途和作用时段**，无需先点击或离开文案。换成侧视图后预览也必须变为侧视图，不能仍显示人物默认封面；待准备的资料显示缺项状态。预览随指针离开关闭，避让屏幕边缘，键盘聚焦也可预览；触屏通过点击查看同样的图片与信息。点击打开引用设置后收起该引用的悬浮预览，避免遮住编辑面板。

点击任一引用，仍留在本镜头，查看和修改：

1. **关联对象与具体媒体**：例如林一 → 正脸身份母图，能直接预览；可改选全身图、侧面图或角色卡，不能只看到资产对象名称。
2. **取用内容**：人物身份、服装、空间布局、道具外形、文字内容、动作、音色等。取人物身份不代表复制原图姿势和背景；一个参考可以有多个合理用途，不限制为固定视觉模板。
3. **作用位置**：当前镜号、时间段、正文段落或某次引用；全镜环境与只作用于局部时段分清。画面站位、动作和空间关系仍由相邻正文与使用说明表达。
4. **修改范围**：点击正文引用时默认仅改这一处；可明确选择本镜的同一引用。不会隐式更改项目人物设定或其他集。多处共享同一默认引用时可一起调整，局部更换形成明确例外。

镜头的资产条汇总正文与镜头级生成输入的实际引用；选择条目能定位对应正文，不另建一份孤立清单。项目资产继续负责总览与来源管理，不能把每一次就地修改都带离镜头页。

## 3. 如何建立、修改和删除

- Agent 创作时直接建立引用并选择最少充分的具体媒体，用户不需要逐个手工标注。
- 用户编辑某段分镜时，在光标处输入 `@`，按人物、场景、道具或媒体名称选择对象，再选具体资料；选择后插入真实引用标记。也可通过“插入引用”入口完成同一动作。
- 替换引用保留周围动作、台词和用户已经修改的文字；删除引用将该处还原为普通文字，或者由用户一起删除词语。其他仍在使用的引用和项目原图保留。
- 普通文本中的名字不自动成为已绑定引用；未完成选择的 `@` 显示待绑定状态。目标对象还没有图片时仍可建立对象引用，明确显示资料待准备，Agent 按当前任务补齐。
- 引用标记以稳定对象、媒体和位置标识保存，名称只用于显示；不依靠同名字符串替换来维持关系。直接编辑、Agent 修改、引用面板和生成说明读取同一份内容。
- 不是每个名词都必须有参考图。一次性背景元素可以只有文字说明，Agent 根据连续性与生成需要判断；有图也不等于每一镜都必须输入该图。
- 对话中“请修改 @第02镜”是任务范围引用，正文中的 `@林一` 是该镜内容引用。消息可以引用两者，但单纯提到资产不等于已改变镜头使用关系。

## 4. 生成时的可核对关系

默认让用户用有意义的资产名称操作。展开“生成输入”后可核对这次真正要发送的图片及其用途、涉及镜头，并查看 Provider 生成说明。

首尾帧、参考图片、动作视频和声音参考属于不同生成角色：同一张图用作人物参考，不自动变为首帧；有需要时在对应生成输入位置显式设置，并只开放当前 Provider 已支持的选项。

编译当前内容时，把正文引用及镜头级输入解析为精确媒体和有序上传列表，再生成 Provider 需要的编号。用户不维护 `<Picture 1>` 这样的易变编号，也不手工同步两套提示词。一个资产的多张图可以服务同一主体，不表示人物重复出场；同一生成组的参考包也不表示每个主体在每一镜都可见。

局部改图时默认保留其他镜头的绑定。本案例前三镜共用一次生成：如果只在第 02 镜增加林一全身图，其他两镜仍用原身份图，则该生成组可能同时需要这两份媒体；不能静默丢掉其他镜头的输入。按 Provider 能力编排并说明实际影响，不能承诺任意时间点都能硬切参考或独立修改原视频像素。

保存绑定后当前设计立即更新，已有视频标为需要更新并继续可看。正在完成完整视频目标时，Agent 自主重编译受影响的请求并继续；仅改引用且没有有效视频制作任务时，不自动付费重生成。原始请求与 Trace 保留为既有视频的来源，新引用预览不能伪装成已提交记录。

## 5. 当前实现与普通验证

正式实现复用 `ProjectDocument`、`ShotTimelineBeat.references`、参考计划与 `H3MediaInput`。`ShotReferenceEditor.tsx` 和 `studio_references.py` 已接通正文位置、具体媒体、用途和回写；镜头只读时仅预览，编辑草稿保存后生效，不建立额外资产状态服务。当前生成输入会校验精确媒体和引用是否仍有效。

Agent 工具与页面编辑写入同一结构；编译器将其与 `ReferencePlan` / `ReferencePack` 及实际媒体解析合并。变更后重新读取当前内容并编译，不沿用旧媒体顺序下的 `<Picture N>`。旧案例允许读取原始 H3 引用来源，迁移补注要标明来源，不能声称原 beat 本来就有这些引用。

页面已验证正文插入、改选图片、修改用途、解除和重新插入后的保存，以及实际图片的悬停预览；后端覆盖精确引用替换、解除、共享素材与过期输入检查。最新镜头编辑验收还覆盖只读预览与显式保存边界，证据见 [产品交付清单](product-delivery-checklist.md) 的 P07、P13。原始 H3 请求仍是对应既有视频的来源，没有为验证新界面而重生成原案例。

2026-09-10 补充：引用的 `usage` 明确区分视频生成参考（`GENERATION`，兼容旧数据的默认值）与剪辑用素材（`EDITORIAL`）。两者都保留媒体、正文位置和悬停预览；后者不进入 H3 图片列表，也不会因为绑定完成就被宣称已经合成到画面。编辑用途时可以选择使用位置。镜头正文不受 H3 单次9张图片限制，数量和兼容性在实际生成请求校验；不能为凑上传数量静默丢掉已声明的生成参考。

实际失败的开场请求包含12份媒体、20处正文引用，在隔离数据副本中用原参数重放成功；相关回归同时覆盖剪辑素材不上传、缺少生成参考仍报错，以及H3真实请求仍遵守9张限制。记录见[保存修复对照](../output/studio-launch-2026-r2/snapshots/reference-save-repair.json)。

镜头已明确选择的当前图片可直接成为生成输入，不再要求另有一个批准标记。这个使用决定不改写原有检查记录，也不表示独立视觉检查通过。拒绝、过期、无媒体及已失效的来源关系仍返回具体问题。相同开场内容在修复前只有两张可用候选，修复后八张均可解析，见[实际选用媒体对照](../output/studio-launch-2026-r2/snapshots/explicit-selected-media.json)。

同一规则也覆盖制作项完成、参考图集、目录导入、派生来源以及声音绑定：明确选用的当前可用媒体可以继续制作，不要求先把DRAFT改成APPROVED。制作项仍需明确填写实际完成结果；只登记候选不等于已经选用。音频类型、实际文件、图片所属对象和来源有效性按用途核对，审核结论独立保留。197项素材、计划、声音及H3引用相关检查通过，相关Pyright为0错误。
