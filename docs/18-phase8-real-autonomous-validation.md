## 范围

## 长镜头和视频检查已经成为 Agent 工具

每条候选不再只看首尾帧。`VideoInspector` 向观察器、候选裁判和 Director Agent 提供：

- 媒体探测：时长、分辨率、帧率和音轨；
- 适应性抽帧：边界帧、均匀时间覆盖和视觉变化点，长镜头提高采样密度；
- 镜内接触表：检查身份、构图、朝向、动作和道具状态随时间的变化；
- 镜间边界表：把上一镜末段和当前镜开端并排，检查空间、角色和道具连续性；
- 语义观察：只报告可见证据与通用 QA 分类，不把稀疏抽帧当成动作不存在的证明；
- Director 修复：比较重生成、换关键帧、拆镜和换覆盖机位，建议可被用户覆盖。

这些能力与门、把手或本轮 S04 无关，可以用于长对白、走位、手物接触、车辆、抽屉、场景穿越等任意镜头。

## 真实运行暴露并修复的通用问题

### 1. 关键帧主参考不能固定选场景图

旧实现总把 Location 作为 GPT Image 编辑主图。人物特写因此可能构图正确但换脸。现在按 `ReferencePlan.requirements` 和 Agent 给出的主体优先级选择主参考；S04 人物特写以林夏批准定妆作为主输入，场景和周衡只作为辅助参考。

### 2. 关键帧 QA 必须和批准资产对照

旧资产检查只看生成候选本身，会把“好看但不是同一个人”的画面放行。现在候选为 Image 1，后续图片为带名称和版本号的批准角色、场景或道具参考；QA 显式检查身份、发型、服装、拓扑和道具结构，不混合不同角色身份。

### 3. 连续性资产不等于本镜头可见资产

旧回退路线把全部绑定参考交给 H3。录音笔虽然只用于跨镜连续性检查且当前镜头要求画外，模型仍因看到道具图而主动画出它。现在生成输入只保留参考计划要求在当前镜头出现的主体；连续性专用资产仍提供给 QA，但不会诱导图像或视频生成。

### 4. 生成提示只描述可见画面

“录音笔在画外、灯灭、尚未放下”仍会增加模型生成录音笔的概率。现在有明确可见主体计划且其中没有 Prop 时，H3 提示只描述应呈现的人物、环境、构图和表演；画外状态保留在结构化连续性账本与 QA 输入中，不进入生成提示。视线文本若包含画外道具名称，也改写为对话方向和银幕轴线。

### 5. 画外元素不可见不是失败

旧关键帧 QA 要求验证画外录音笔的右手、灯态和动作阶段，属于照着答案出题。现在只有计划要求可见的接触、左右手和状态才必须读得出来；明确画外的元素没有出现即为合规，可记录“状态无法由此帧验证”，但不能因此拒绝候选。

### 6. 恢复和重复提交

H3 调度器会先提交同批队列再公平轮询；重启时按 request fingerprint 复用已确认的 Provider Task ID，并避免为同一失败父任务创建多个重试子任务。语义审查短暂断开时最多自动重试三次，恢复后从 SQLite 的 `QA_AND_REPAIR` 状态继续，不重新生成已完成视频。

## 最终画面结论

最初完成的 `manifest-v2` 在整片抽帧中发现 S04 女主身份和批准定妆不一致，因此没有作为最终交付。`manifest-v3` 的 S04 使用批准定妆衍生首帧，身份、短发、米白风衣、人物左右位置和视线连续；录音笔与持物手没有误入该镜头。最终自动 QA 只保留一个 `MEDIUM` 构图建议：景别比声明的严格面部特写略松，没有 `HIGH` 或 `CRITICAL` 问题。

整片技术检查已经通过，但以下仍需人工或后续工具确认：

- 完整观看时的叙事节奏和总体观感；
- 五句锁定对白的逐字正确率、说话人和跨镜声线；
- 原生音效、雨声和呼吸停顿是否符合导演意图；
- E007 的另外两次独立真实运行与三人盲评。

本次因连续发现并修复实现缺陷，对该持久化运行增加了补偿修复轮次，最终 `repair_round=5`。产品默认仍保持两轮有界修复；补偿轮次不是新的默认策略，也不代表以后允许无限重试。
