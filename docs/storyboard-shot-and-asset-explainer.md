# 真实案例里的分镜、视频与资产

更新：2026-09-09。本文件回答本轮产品讨论中的真实数据问题，并解释新布局的依据。字段与数字来自已经完成的校园案例；产品布局建议仍待用户讨论，不等于新界面已实现。

## 1. 用户记忆中的时间段描述

`[1～3s] + 详细描述`属于按时间编排的拍摄、动作和表演说明。本项目实际有两层：

- `ShotPlan.timeline_beats`：一条叙事镜头内的时间段，包含画面、构图、运镜、动作、表演、情绪、对白引用和声音。每镜单独从0秒计时。
- `H3RoutePlan.decisions[].prompt`：提交给视频模型的实际生成说明，将一个或多个分镜编排为同一视频片段。真实首组使用 `[Shot 1] [0.00-4.00 seconds]`、`[Shot 2] [4.00-8.00 seconds]`、`[Shot 3] [8.00-13.00 seconds]`；这里从该次生成片段的开头计时。

这些是分镜与生成说明的详细内容，不增加一个制作阶段。分镜不一定先有漫画格或专用分镜图；本案例先有结构化文字设计和相关人物、场景、道具参考。

## 2. 第02镜的真实例子

镜号：`shot-independent-v7-001b`；预计4秒；林一报出“十四元”。以下对真实字段作易读整理，保留原台词与时间：

> **[0.0–1.8秒 · 本镜头内]** 刘阿姨把装好红烧肉与青菜的餐盘放回窗口。餐盘占画面下三分之一，林一扫过上方八元与六元价牌。镜头平视小幅后退接住餐盘，响起餐盘触台声。
>
> **[1.8–4.0秒 · 本镜头内]** 林一平静说：“十四元。”镜头先保持嘴部自然发声，再移焦到刘阿姨停在饭卡机前的手。林一笃定，刘阿姨抬起上眼睑、手指悬停；食堂底噪轻降但不中断。

同镜还有叙事目的、人物位置与视线、道具开始/结束状态、转场、对白、50mm机位与景深等完整描述。产品默认给用户看画面、动作、台词、情绪和时间；摄影参数与实际Provider语法可展开查看，不能只剩一句摘要，也不直接把JSON当正文。

## 3. 一条分镜与一次视频生成不是同一种计数

整个真实案例：21条叙事镜头，12个生成组，分镜计划131秒；12段原始视频实际共135.68秒；最终按21个镜头来源窗口装配为131秒。

第一组的对应关系如下：

| 叙事镜头 | 分镜计划 | 在源视频内使用的窗口 | 成片中的窗口 |
| --- | --- | --- | --- |
| 01 / 001a | 点餐，4秒 | 0–4秒 | 0–4秒 |
| 02 / 001b | 报“十四元”，4秒 | 4–8秒 | 4–8秒 |
| 03 / 001c | 刘阿姨质疑，5秒 | 8–13秒 | 8–13秒 |

本组实际向H3要求13秒，回收原片13.67秒，成片使用其中13秒。第一组恰好在片头，两种窗口看起来相同；第二组的源视频内0–7秒和7–14秒，在成片里是13–20秒和20–27秒。因此界面必须写明“镜头内时间 / 源视频内时间 / 成片时间”，不能只显示没有解释的秒数。

同一个原片可以按窗口预览出三个叙事镜头，无需为界面再物理复制成三个文件。修改某一镜头时，Agent必须知道它与哪些镜头共用原片；实际重新生成可能涉及整个片段，不能承诺每镜都能在原片上独立改像素。只在确实需要时重做相应片段，继续保留不相关结果与人工剪辑。

## 4. 资产对象与资产文件

已完成核心资产包有29份媒体。本轮产品展示将它们按语义归为11个对象：3个人物、2个场景、6个道具/画面载体。这是根据实际文件的产品归类，不等同于后端每一个原始资产行或11份参考包的含义。

- 林一、刘阿姨、秦校长：每人身份母图、正面全身、侧面、背面和组合角色卡，共15图。
- 学校食堂、高考考场：各一张四向场景卡，共2图。
- 计算器1图；菜价牌载体及两个文字层3图；协议载体及文字层2图；录取通知书载体、封面与内页3图；手机载体与屏幕内容2图；食堂电子屏内容1图，共12图。

第一生成组实际带6张参考图，服务于林一、刘阿姨、学校食堂和菜价牌4个语义对象。用户首先需要看到“有哪些人物、场景和道具，准备到哪了”，再展开看这些对象的具体图片；6张参考图不能被写成6个角色或6份独立场景。

本案例没有单独生成TTS或音乐，使用视频原生声音。声音分类可以显示无独立音频素材，不应为填满资产页而制造配音文件或待补任务。

## 5. 页面建议的依据

建议主入口为“剧本 / 镜头 / 成片”，分镜设计与视频结果都属于同一个镜头工作区。理由是两者沿用同一组21个镜号，用户修改的也是同一叙事对象；合并后能直接核对计划与结果，避免在两个相似列表里重复寻找。整体分镜表仍可阅读和导出，详细的逐时段设计不删除。

项目资产作为固定项目工具入口，统一展示完整对象清单、生成中和待补项、引用位置与具体文件；各内容页的缩略引用条打开同一份资料。人物多视图和场景角度是不同用途的文件，不是历史版本，也不是第五个必经制作阶段。

Agent的运行边界由用户目标决定：要求完整剧本则完成剧本后结束，要求成片才继续制作视频。三页同样不是固定三步工作流。用户在任务中选中第02镜提出修改，Agent读取其当前分镜、引用与媒体来源，完成修改后说明影响和下一步；是否继续制作依原任务和最新意图判断。
