> 权威定义：[产品 PRD 与里程碑](product-prd-and-roadmap.md)。修改来源与保留内容见 [改版记录](product-redesign-notes.md)。

## 1. 产品整体形态

默认使用方式是：**用户输入一段创作要求，Agent 理解当次交付目标并持续完成；用户观看内容逐步出现，随时指定任何一处进行修改。** 用户要完整剧本，写完剧本就收尾并回复；用户要完整视频，才继续完成必要的分镜、资产、镜头和成片。页面组织不决定执行顺序，也不要求用户逐页点击生成。

当前主推三个内容入口：**剧本 / 镜头 / 成片**。镜头工作区让同一个镜头从分镜设计到实际视频保持在同一处：用户选中第 05 镜，就能同时理解准备如何拍、使用哪些资产、实际拍出了什么。分镜仍是完整可读、可修改和可导出的内容，只是不再单独占据一个主页面。

交付边界由 Agent 理解自然语言意图判断，不能靠关键词、正则或页签固定路由，也不要求用户预先选择“停止阶段”。目标已经达到时结束任务并说明完成内容，不自行追加下游制作。

右侧 Agent 对话和制作任务持续可见。用户已有剧本、图片或视频时仍可直接进入相关部分导入，Agent 根据当前内容和目标补齐后续工作。

顶部主推三个内容入口。保存状态轻量显示；导出放在成片页，制作记录放在右侧详情。没有画布、节点连线、独立历史页和版本切换入口。

项目资产是始终可见的项目工具，不是另一项必经制作阶段。素材库作为“从素材库导入”的来源入口，不与项目资产并列成两套内容管理。

### 1.1 从一句话开始的默认路径

1. 首页输入创作要求，可附图片、文本或已有媒体，点击“开始”。要求可以是完整剧本、局部分镜、完整视频或修改已有内容。只处理当前目标需要的偏好，确实影响任务且无法合理推断的信息由 Agent 简短询问。
2. 从创意开始写剧本或制作视频时，打开本集剧本；已有内容的局部任务定位到对应内容。写作过程中，右侧显示实际正在写的场次，中央逐场呈现完成内容；人物、场景等所需对象逐渐出现在本集资产区，即使还没有图片也能看到。
3. 如果目标是完整剧本，完成正文后自动停止并回复；如果目标是完整视频，Agent 自行安排必要的分镜、资产准备、镜头生成和成片工作。已具备输入的工作可以并行进行；页签显示已有结果和正在更新的内容，无需用户手动逐页推进。
4. 用户可以跟随制作查看新成果，也可随时浏览、播放或编辑任何已有内容。用户主动离开当前生成位置或开始编辑后，自动跟随暂停，右侧继续更新并提供“查看”和“继续跟随”。并行任务的每次更新不会不断抢走页面。
5. 用户选中场次、分镜、镜头或资产，发送定向修改要求。Agent 修改当前内容、说明影响，并结合原任务与这次新意图决定是否继续。正在执行完整视频目标且用户没有收窄范围时，同步相关输出后继续成片；用户说只改剧本，就在剧本修改完成后回复，不自动重做视频。
6. 达到当次交付目标后收尾。若目标是视频，成片可用后直接播放，用户继续提出修改，或进入剪辑和导出。

一个项目可有多集，共享核心资产；单条视频默认是一集，不先要求用户建立多集结构。手动新建、导入、生成或替换保留为内容操作。Agent 始终围绕有效的用户目标工作，不从页面位置推断用户已授权整集视频制作。

## 2. 三个内容入口各自负责什么

| 页面 | 中央主要内容 | 可直接执行的动作 | 产生或使用的内容 |
| --- | --- | --- | --- |
| 剧本 | 故事概述、场次目录、按场次展开的正文和对白 | 直接改文稿、添加或调整场次、导入文本、让 Agent 写作或续写 | 当前剧本；人物、场景与创作参考 |
| 镜头 | 按场次排列的一份镜头列表；选中后呈现该镜完整分镜设计、资产引用和实际视频 | 阅读与修改设计、查看/替换资产、播放视频、提出修改、调整顺序、导入或重新制作、剪辑 | 同一镜头的计划与结果；可展开生成编组、源视频和采用区间 |
| 成片 | 连续视频预览、当前时长与画幅、字幕和声音入口 | 自动组接、剪辑成片、播放、导出视频和制作记录 | 当前整集剪辑与交付文件 |

合并的依据是：分镜设计回答“这一镜准备怎么拍”，实际视频回答“这一镜拍出了什么”，它们属于同一个镜头。分开成两个主页面容易产生重复列表、选择丢失和计划与结果难以比较的问题。合并后用同一个镜号、一次选择、一组资产引用连接两者；不是把两张仍然分离的列表藏进两个标签。

真实校园案例应显示 **21 个分镜计划对应 21 个叙事镜头结果**。底层有 **12 段生成源视频**，部分源视频覆盖多镜；源视频数量不冒充镜头数量。界面按镜号播放相应区间，不要求为展示而复制拆出 21 个新媒体文件。源视频、生成编组和片段范围默认折叠在详情，供需要了解制作的人查看。

## 3. 剧本：边生成边看，随时编辑

- 左侧是场次目录，中央呈现完整文稿；选中一场或一段文字后，可让 Agent 只改这一部分。
- Agent 生成完整剧本时，右侧显示实际动作，如“正在写第 3 场：食堂结账”。每完成一个场次并保存，正文与目录自动增加该场。
- 供应商有实际文本增量时，正在写的场次可呈现“生成中”草稿。结构化输出尚未完成时只作预览，不能用半截 JSON 替换正文。
- 从“开始制作”进入后可跟随新成果；用户主动浏览或编辑后停止自动跟随，不抢走阅读位置或光标。提供“查看新场次”和“继续跟随”，由用户恢复。
- 用户编辑过的段落继续保留。无冲突的新增内容直接加入；同一处有冲突时，Agent 读取当前正文再处理，只在确实需要取舍处展示简短建议。
- 人物、场景和创作参考放在默认可见、可展开的“本集资产”区域，直接显示名称、缩略图和缺项。这里与项目资产是同一清单，可以查看设定、导入图片，或让 Agent 补齐所需内容。

## 4. 镜头工作区：同一镜的设计、资产和实际视频

左侧或中央窄栏按场次排列镜头，镜号、内容摘要和状态始终一致。选中镜头后只保留一个当前对象：宽屏可把“分镜设计”和“视频结果”并列，窄屏在同一镜头详情里切换两种视图，切换不改变镜号或选择位置。参考资产在共同引用区显示，点击可直接查看详情。

还没生成视频的镜头也正常出现完整设计和“等待生成”等状态；生成后视频就出现在原镜头内，不要求用户去另一张结果列表寻找。需要整体审阅或交付时可打开“阅读完整分镜表”或导出分镜表，返回仍保留当前镜头，不再增加一个独立制作阶段。

### 4.1 分镜设计

每条分镜显示镜号、所属场次、画面作用、参考画面、景别/机位、动作、对白和预计时长。采用清楚的图文列表，支持顺序调整和多选。展开后应读到完整设计，不能只有一行摘要或一个提示词输入框：

镜头默认只读，标题区显示“编辑分镜”和“让 Agent 修改”。进入编辑后显示“保存分镜 / 取消”、已改字段与草稿提示；切换镜头或页面保留草稿。所有设计字段、逐段对白引用与图片绑定遵循同一保存边界。并行更新保留草稿，可合并最新内容而保留人工改动。

“设计时长（秒）”在编辑态支持小数。修改总时长按比例调整分段；单独修改起止时刻时相邻边界联动，首段从 0 开始、末段覆盖总时长。空值和倒置区间阻止保存。保存后镜头、正式分镜及镜头组汇总同步；已有视频保留。

同时显示“本镜素材”和“成片采用”时长。设计时长不是素材裁切指令；裁切、拆分与变速决定采用时长，不自动改写分镜中的逐时段描述。详细规则及验收见 [镜头编辑与时长](shot-editing-and-timing.md)。

- 这一镜要表现什么、人物如何表演、画面如何开始和结束。
- 景别、机位、运镜、场景位置与人物关系。
- 完整动作、对白、声音，以及实际需要的分段时间描述。
- 引用的人物、场景、道具、声音和参考图；点击引用直接进入该对象详情。
- 对应剧本段落的定位入口，以及同镜头的视频结果。

`[1–3s] + 详细描述` 这类内容是带时间的画面与声音设计。单镜 `timeline_beats` 从该镜头0秒计时，生成说明则可能按整段源片中的多个镜头安排计时。界面分别标明“本镜头内时间”“生成片段内时间”，两者又都与最终成片时间码分开；分镜不等于一张图片，也不等于 Provider 的完整请求文本。

例如真实 `001` 生成组含 `001a` 的 0–4 秒点餐、`001b` 的 4–8 秒“十四元”、`001c` 的 8–13 秒质疑。它们是镜头列表的三个对象，各有分镜设计与实际视频区间；在生成组详情中合起来成为一段 13 秒的计划。H3 实际源视频为 13.67 秒，后期采用其中 13 秒。计划时长、实测源视频时长与最终采用范围分别显示，不把三者写成同一个数。字段、完整原文及证据见 [真实分镜、镜头与资产说明](storyboard-shot-and-asset-explainer.md)。

人物、场景等通过正文中的 `@` 标记、可见引用条和就地选择器维护。进入编辑后添加、移除或替换引用，并随分镜保存，同一对象仍来自项目资产。必须能查看该处实际使用的图片、取用用途和作用时段，不能只显示整镜资产清单。局部“生成分镜图”“导入图片”“制作这个镜头”是可选内容操作；正在执行的完整制作目标会自行补齐真正需要的资产和媒体，不要求用户按页确认。

### 4.2 视频结果

选中镜头的视频结果提供可播放预览、实际采用时长、声音状态和“剪辑”按钮。主要操作是播放、修改要求、生成/重新生成、导入或替换视频。其镜号与旁边或另一视图中的分镜设计完全相同；图片、对白、配音、音效在同一镜头的引用区查看，点击后进入项目资产详情。

默认按叙事镜头显示“等待素材 / 生成中 / 可播放 / 正在更新”等实际状态；有已知数量时显示可用镜头数。源视频包含多镜时按入点和出点播放当前镜头，展开详情才显示“来自生成组 001，源视频 13.67 秒，采用区间 4–8 秒”等信息。原始文件也可在项目资产的所有媒体中查看。

每个镜头只展示当前使用的内容。生成过程中已有媒体可继续查看，新结果成功回写后更新当前媒体；失败时保留可用内容并显示具体问题。用户主动生成多个选项时可以选择一份作为当前素材，但不建设历史版本树或强制候选审批流程。

### 4.3 正文中的 @ 引用与图片预览

分镜文字中的 `@林一`、`@学校食堂`、`@红烧肉价牌` 等是可操作的真实引用。默认由 Agent 建立，用户编辑某一时段的文案时可在光标处输入 `@`，选择资产和具体图片；普通名字不能仅靠染色冒充已绑定。

- 鼠标悬停直接预览该处绑定的具体图片，显示名称、用途与作用时段；更换视角后同步更新预览。键盘聚焦也能查看，触屏点击获得同样信息。
- 只读时点击可查看；编辑态点击在镜头内打开引用设置：图片预览、具体资料、取用内容/使用方式和修改范围。默认仅修改当前这处，也可选择本镜的同一引用，不隐式改动全项目人物设定。
- 人物身份、衣着、空间、文字层等参考用途与正文中的动作、站位共同表达“哪里使用什么”；选人物图不代表复制原图背景或把它自动设为首帧。
- 镜头资产条、正文引用和生成输入来自同一关系，修改或删除后同步更新。待补图片显示资料缺项；保留不需要图片的纯文字元素。
- 展开生成输入可核对实际选择的图片、涉及镜头和生成说明。Provider 的图片编号由当前有序媒体计算，用户不手工维护编号或另外一份提示词。
- 对话中的任务范围引用与镜头正文中的内容引用分清；在消息里提到资产，不代表已经改了该镜的绑定。

当前实际记录在 H3 请求中保存了有序图片与别名，但案例首组三镜的逐时段 `references` 为空，历史记录不补写为人工逐句确认；正式产品已支持文案位置、精确媒体选择及回写。实现事实、交互规则与来源见 [镜头文案与资产引用](shot-asset-reference-interaction.md)。本轮示意中的引用标注不回写或改写原始 Trace。

## 5. 镜头与成片的剪辑入口

用户最新要求覆盖此前“定位整集片段”的交互。镜头入口打开仅含当前镜头的 LTX 编辑视图，局部时间从 0 秒开始，原声与本镜字幕随同显示；其他镜头不出现在这条局部时间线上。

- 明确“保存镜头剪辑”和“取消并返回镜头”；局部剪辑不自动写入。保存后，镜头预览和采用时长即时更新，成片采用同一编辑结果。
- 保存按镜头范围合并，长度变化顺移后续镜头、关联声音和字幕；保留其他媒体和设计时长。整片配乐等跨镜内容保留原长，并提示检查节奏与结尾。
- 已在成片多处使用时先选择本次修改的位置；连续拆分仍在当前镜头中编辑。已从成片移除的镜头再次保存时，按钮明确“保存并加入成片”。
- 局部文档带作用范围，整集保存入口拒绝将局部内容覆盖到全片。两处没有独立内容真相。
- 裁切、拆分、速度、声音和字幕继续复用 LTX 非模型代码；不接入 LTX 模型生成。用户尚未保存的剪辑不会冒充 Agent 已读内容。
- 没有视频时仍显示完整分镜、参考、设计时长和“生成 / 导入视频”，剪辑入口不可用。采用时长显示尚未采用。


## 6. 成片：连续播放、完整剪辑和导出

成片页直接连续预览当前保存的整集剪辑，展示画幅、实际时长、字幕/声音，并提供“剪辑成片”和“导出”。单镜头保存后预览立即更新；旧 MP4 不会被悄悄改写，下载旧文件与重新导出有明确区分。完整制作目标执行中，Agent 按可用镜头持续完成组接与收尾，不等待用户再点一次“自动组接”。尚未形成可播放结果时显示实际正在处理的内容与可用镜头数；用户也可只委托组接已有视频或自行安排。

点击“剪辑成片”后，同一 LTX 编辑器展示整集多轨时间线和大预览，可调整镜头顺序、整片节奏、转场、字幕、配乐、音量等。右侧作用范围显示当前集成片或选中的片段。退出剪辑回到成片预览，不创建第二个项目。

更换镜头媒体时，尽量保留时间线上已有的裁切、字幕、音量、配乐和其他人工编辑；如果新媒体无法容纳已有裁切或转场，仅提示对应位置需要调整，并保留当前可用结果。刷新页面、Agent 完成生成或自动组接都不能把用户的时间线重建回默认状态。

导出围绕当前集当前剪辑执行。默认预填项目画幅和可用规格，也可选择实际支持的分辨率、帧率及字幕处理。用户可在导出期间继续编辑；该次导出使用开始时取得的有效内容，完成后提供文件和播放入口。

**制作记录继续保留，用于产品发布会 PPT。** 产品提供制作记录导出：剧本、分镜、素材清单、镜头与成片文件索引、运行摘要和完整 Trace。用户补图和开发者修复如实记录；当前内容直接修改不影响过程资料。

## 7. 右侧 Agent、范围与任务进度

右侧保持“制作任务 + 对话 + 输入框”的稳定位置。任务摘要直接说正在做什么、处理哪个对象和最近完成什么，不要求用户理解 Leader、Worker 或内部工单名称。

- 任务状态包括正在处理、等待结果、需要补充、暂停、完成与失败。已知具体数量时显示实际完成项；未知总量时不制造百分比。
- 新场次、新分镜、图片或视频保存后，中央相应内容同步更新；右侧可以点击“定位”进入该对象。
- 持续展示当次目标、当前动作和下一项已确定工作。完整视频任务可显示“剧本第 3 场已完成；正在规划食堂分镜”；完整剧本任务在正文完成后显示“剧本已完成”并收尾。具体计划可随结果调整，不把阶段条当作固定工序或四次人工确认。
- 过程详情保留实际模型、推理强度、调用动作、输入范围、工具结果、耗时、上下文规模、供应商返回的用量和 Trace。没有提供的用量明确显示未提供。
- 展示可观察动作和内容草稿，不伪造模型思考内容。交互示意中的演示状态与真实运行有清楚标识。
- 暂停停止后续派发；已提交的外部任务继续追踪和回收。恢复先核对现有任务再继续，避免断网后重复提交。
- 用户与 Agent 可以同时工作，任务不会遮住正文或整个页面；冲突局限在相关内容。

范围沿用此前规则：进入某一集后默认针对当前集；选择场次、分镜、镜头或时间线片段成为下一条消息的引用。用户可以取消引用或主动切到项目范围。跨集和共享素材明确标示所属范围，用户消息中的明确意图优先。

发出消息时确定任务范围，浏览或切换阶段、集、设置不会重新指向正在运行的任务。各集保留对话草稿、引用和编辑位置；实际模型输入只携带当前任务所需内容。

### 7.1 制作过程中定向修改

用户选中第 2 场说“这段对白太生硬，改自然一些”，或者选中第 05 镜说“这里不要特写，改成能看到两个人的中景”。输入框明确显示引用对象，Agent 读取当前内容，直接处理这次修改；是否继续原目标，要结合原任务与本次新意图判断：

1. 明确正在修改的对象和要求；不要只回复“收到”，随后让用户猜它是否生效。
2. 保存修改并刷新对应正文、分镜或资产。回复具体改了什么，不展示虚构的思考过程。
3. 根据语义判断哪些下游内容受影响。例如对白改变可能需要更新分镜对白、声音和字幕；镜头景别改变可能需要更新相关视频。只处理相关部分，保留其他镜头与人工编辑。
4. 在已授权且仍有效的整集自动制作任务内，自行同步必要的相关媒体和成片，说明影响及接下来在做什么，然后继续完成整集。不默认逐步要求用户批准。若最新要求已收窄为“只改剧本”，则按新范围完成并回复，不以旧目标为由继续生成视频。

回复应像“第 2 场已改成自然的问答，保留原情节；现在同步第 05 镜的对白、声音和字幕，随后继续制作剩余镜头”，并附对象定位。不要仅给一段建议而不修改实际内容。

用户明确“只改文字”“只处理这一镜”时尊重该范围；超出范围的相关输出可标明待更新，不自行扩展为全片重做。没有正在进行的整集制作任务、用户只是手动更换人物参考图时，保存当前参考并标明受影响媒体待更新，提供“让 Agent 同步相关镜头”入口，不无声启动全部媒体生成。

同一内容正在执行旧要求时，只调整相关工作。尚未提交的依赖任务采用当前新要求；已提交且无法撤回的外部任务继续追踪回收，不假装已经取消，完成后也不能用旧要求结果覆盖当前内容。已有可用结果继续显示，需替换的部分标记“正在更新”。无关任务可以继续，用户已生效的修改与编辑位置保持有效。

## 8. 当前内容、素材和保存

镜头分镜先编辑再显式保存或取消，单镜头剪辑同样明确保存；成片编辑保留常规自动保存与手动保存按钮。界面清楚显示未保存、保存中、已保存或保存失败。常规撤销/重做保留，不展示版本号、旧版采用、比较历史或分支恢复。

项目共享素材修改后，使用该对象的引用读取当前内容。已经生成的媒体不会因为参考图片修改而自动变样；需要时按任务目标重生成。外部导入素材走相同路径，跨项目复用时将选中的素材导入当前项目，各项目后续编辑独立。

底层只保留恢复运行、正确引用媒体和并发保存所需的标识、时间或更新校验。现有 ArtifactRef/version 与历史实验数据兼容读取，不因改版而删除；后续不为版本管理新增产品或框架。

### 8.1 一份项目资产清单，看清已有内容与缺项

左侧固定“项目资产”入口；内容页面上方保留简短、默认可见的“本集资产”区，露出主要人物与场景的名称、缩略图、可用状态和缺项数。点“全部资产”在中央展开完整清单，右侧 Agent 继续可见。

清单按“全项目 / 本集 / 当前选中内容”筛选同一批对象，不各建项目素材、本集素材与镜头素材的数据集合。“本集”和“当前选中内容”表达使用关系；项目资产详情可以查看在哪些集、场次或镜头中引用，并定位过去。

资产工作区区分两种查看方式：

| 查看方式 | 展示什么 | 用户需要看清的内容 |
| --- | --- | --- |
| 核心资产 | 人物、场景、道具、声音等项目对象 | 叫什么、设定是什么、需要哪些参考、当前已有什么、哪里还缺、用在哪些内容里 |
| 所有媒体 | 导入或生成的图片、视频、音频文件 | 媒体预览、所属资产或镜头、来源、尺寸或时长、是否被当前内容使用 |

核心资产在 Agent 确定需要时即加入清单，**没有生成文件也显示名称、设定与待补项**。例如“林一”可以先有角色描述与“待生成人物参考”的占位，避免用户以为项目还没有这个人物。灰色缺项卡片是内容状态，不是等待审批。

- 人物详情：当前人物设定、主参考、正面/侧面/四视图等所需视角、声音及使用位置。各视角属于同一个人物的不同参考，不是历史版本。
- 场景详情：空间说明、主参考、所需角度与使用位置。道具和声音使用相同的清楚结构，按实际任务需要呈现字段。
- 卡片状态：待生成、生成中、可用、需要补充；显示真实状态与具体缺什么。部分已有内容、部分缺项时分别显示，不用一个“完成”掩盖缺口。
- 详情操作：直接改设定、导入参考、让 Agent 补齐、选择当前使用的参考；内容中的引用条可直接点击到这里，也可就地选择或替换引用。
- 所有媒体按图片/视频/音频筛选；显示用户导入、素材库导入或生成来源，并关联到对应资产或镜头。生成源视频与它覆盖的叙事镜头关系可展开，不混成多个无法辨认的重复文件。
- 外部生成受阻时显示具体所需内容、参考图与说明发送顺序。用户补入文件后回到同一对象，Agent 按原授权任务继续，不另开一套补图流程。

“从素材库导入”是选择既有内容的来源入口；导入后进入当前项目资产清单，后续按项目内对象正常查看、引用和修改。首版不需要一个与项目资产同权重、用途相近的独立素材库页面。

## 9. 创作方法、设置和高级入口

- **外观与配色**：设置默认打开“外观”，提供雾白蓝（默认）、暖纸米、松林绿和深空灰四套预设。每个选项展示工作台缩略预览，点选即时生效并保存为本机应用偏好，重开后沿用；支持键盘方向键切换。说明、占位提示、状态和正文分别使用统一语义色，任务面板的部分辅助文字提高到 11px。剧本、镜头、资产、成片、设置和悬停图片预览共享配色；媒体及 LTX 剪辑区保留中性的深色底，并提高时码、素材提示等辅助文字的对比度。
- **创作方法**：以方法名称、用途、适用情形和清楚的说明阅读，不把上游文件树、角色矩阵与配置 JSON 直接当产品页面。详细内容按“输入、方法、输出、检查、例子与来源”展开。
- **设置**：语言 Agent 默认目标为 GPT-6 Astra / xhigh；图像、视频和声音 Provider 分别配置。模型状态显示实际配置，不用展示标签冒充已成功切换。
- **高级媒体工作流**：ComfyUI 从相关媒体的高级操作进入，执行结果回到该内容。默认使用路径保持直接可用。

Skills 与提示词的具体整理和模型迁移见 [Agent 重构方案](agent-skills-and-model-redesign.md)。
