# 透视缩小的细线与摄影纸色

状态：2026-09-12 第十三轮调试修复，产品实现及相关回归完成。原任务于 08:36:37 暂停，34 个图片任务已落盘、视频任务及 Take 为零。以下真实图片问题与离线方法已复核；尚未在产品运行中生成新候选或重做空项目验收。

## 本次实际问题

同一场景需要保留报价单红色修改、确认签名和情况说明的经办／复核签名，同时让两张纸分别面向桌子两侧。已经正确制作的源图经过局部透视后，原本连续的表格与签线变成周期断点，纸面边缘还出现少量白亮点。

- s04 `asset-version-85afd1b353c8` 使用摄影报价源 `asset-version-d99209b73470`，实际保存的模式为 **replace**。产品检查为 4.5 分，记录轻微采样缺陷并建议作静态参考；不能写成原图完全无缺陷。
- s13 `asset-version-83f51ba22324` 使用白底准确字版 **multiply**。纸面灰贴片减轻，但表格与签线仍断续，字版姓名也不是摄影原手写。实际检查为 4.1 分，仅适合不承担逐字阅读的收纸前构图参考。
- s13 先前的摄影版 `asset-version-71b7a63db253` 保留原手写，却有灰色内矩形。直接把摄影灰白底改为 multiply 会进一步压暗底图，不能把改混合模式本身当作去底方法。

三者都是实际候选；各自原请求、基底与源图在忽略输出目录和任务记录中保留。离线重放前两张及摄影版的旧请求，均与原落盘图片逐像素一致，因而可以分别检查采样和纸色，而不让再生成的人物、几何或字体变化混入比较。

## 采用的公开方法

[Pillow 的滤镜说明](https://pillow.readthedocs.io/en/stable/handbook/concepts.html#filters)明确区分 resize 与其他变换：透视变换的 BILINEAR 和 BICUBIC 分别使用局部 2×2、4×4 邻域；[Image.transform](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.Image.transform)并不接受 BOX 或 LANCZOS。因而不能简单将原透视参数改成 LANCZOS。本地方法先在目标纸面的局部包围框内提高采样密度，再用 BOX 降至最终尺寸；通常只提高局部区域的采样密度，临时像素始终有上限，也不改变纸角对应关系。

[Adobe 的 Levels/Curves 白点方法](https://helpx.adobe.com/photoshop/using/adjust-color-tone-levels-curves.html)从实际图像选取白色参照；本地只采用其中最小的输入白点映射思路。每通道使用 `min(255, round(channel × 255 / white_point))`，alpha 保持原值，再将处理后的摄影内容合到已经空白且光照正确的载体。它不重写文字或生成签名，也不等同于 Photoshop 完整色彩管理。白点必须按本图空白纸面选择；它会削弱或抹掉浅色笔迹，不能作为通用默认值或无损提取承诺。

## 离线比较及边界

同一几何的局部 4× BILINEAR → BOX 在 s04、s13 中使细线连续，减少白边尖点。独立看图确认必要字形、红色修改和原方向保留；细字稍柔，不补出源图缺失细节，也不证明影片中的实际阅读时间。s04 两个实际边缘位置的 RGB 从 255/255/255、249/250/251 分别变为 236/236/239、219/220/221。

每个方案各做三次本地完整渲染及保存，s04 中位耗时 0.435 → 0.502 秒，s13 为 0.456 → 0.486 秒；最大临时局部采样图分别 6,162,688、3,692,000 像素。全帧 4× 则会达到 58,982,400 像素，本试验未采用。此为离线算子时间，不能当作 Agent 总耗时或端到端提速。

两张真实请求均没有 protected_regions。另在临时请求副本中添加 41×41 保护区，1,681 个保护像素及纸面外像素逐值不变；这是独立本地控制，不冒充真实制作中已经覆盖保护区。

摄影 s13 源图的空白纸面样本约为 RGB 219–235。显式比较白点 235 和 220：235 较保守，仍有可见灰矩形；220 在本例明显减轻贴片，并保留原摄影手写姓名、红划线、红字及主要细线。将 220 与局部抗锯齿合用，既保留原手写形状，也改善透视后的断线。达到阈值的浅灰会被变白，不能将 220 固定用于别的图片。

试验文件位于 `/tmp/plane-aa-study/` 和 `/tmp/plane-levels-study/`，未写入项目或替换采用结果，也没有为试验调用图片 Provider。

## 最小产品改动

继续使用现有 `image.composite_plane`。缩小时按透视局部倍率选择有像素上限的 2–4× 采样，1:1 与放大保留原方式；最终目标边界和保护区仍按原图像素应用。极大区域无法在上限内提高采样时保留原方式，不拒绝先前合法输入。纸色只增加可选输入白点，默认不调整；原图、alpha、文字内容、当前采用和镜头绑定不自动改变。

Agent 方法按具体缺陷选择原摄影、已有字版、局部合成或实际重新生成。不能只为消除灰底而不必要地替换已有有效手写；也不能仅因字版更整齐就把它当作与原签名相同。新候选仍按实际镜头用途检查后采用，不增加固定审批或每张图必做的步骤。

字段为 `source_white_point: int | None`，默认 None，仅接受1–255的明确整数。实际完整请求会随候选 source.prompt 保存，并进入既有 QA 的 candidate_creation 和可选平面建议 Schema，不另建重复元数据。Tool调用、服务重新打开及QA输入回归核实数值保留，current／approved／镜头绑定不改变，没有新图片任务。没有为了加参数增加工具调用或固定步骤。

渲染器的临时高密度采样上限为8,000,000像素。回归发现不缩小的局部区域仅因矩阵换原点也可能差1级色值，因此1:1及放大完整保留原全帧1×变换；仅缩小采用局部高密度采样。测试中的4.5倍缩小、1像素黑白条纹由旧标准差88降至16，仍非精确面积积分；测试检查至少75%的振幅衰减与正确平均覆盖，不把有限4×采样写成完全消除所有频率混叠。半透明RGB使用Pillow既有预乘采样合同作精确比较，避免把LUT公式与后续量化误差混为一谈。

最终12文件联合回归 **153 passed / 13.97秒**，包括实际采样、透明／遮罩／多层与方向、Tool持久化、QA、Skills及Registry；5个相关Python文件Pyright为0 errors。OpenAPI及前端类型重新生成后无差异，本轮未修改前端，不重复前端构建。首轮联合中3项新测试的预期差异已按上述有界采样和Pillow量化合同校正；此后又补入非全图1:1／放大兼容测试并修复对应原点差异，最终全套通过。
