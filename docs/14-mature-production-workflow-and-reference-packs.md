# 成熟 AI 短剧制作法与参考资产包

## 结论先行

真人都市短剧不应把“一张三视图 + 一段提示词”当作稳定一致性的完整解法。成熟产品和开源项目的共性是：

`Script Breakdown → Project Bible → Character / Location / Prop Packs → Storyboard / Animatic → Shot-specific Reference Selection → Video Takes → Review / Retake → Timeline`

三视图可以是角色设计与人工审核工件，但不应默认把一张前/侧/后合成宫格直接传给每个下游图像或视频模型。本项目改用“分离的角色身份包 + 按镜头选参考图”。

## 1. 为什么不再继续纯抽样

小样本实验仍然有用，但它应用于验证明确假设，不应代替制片结构。之前的实验已经证明：

- S01 用合成双人首帧锁住了机位、人物位置和无文字灯箱；
- S02 用角色 + 场景 Reference 锁住长对白近景；
- S03 用周衡 + 场景 + 录音笔 Reference 取得 5/5 人工通过；
- S05 用镜头级首帧锁住右手落笔和道具状态；
- S08 在角色、服装和道具大体成立时，仍出现“右手推右门，左门自行打开”。

因此 S08 的瓶颈不是“再多抽几次”，而是当前输入没有把门的机械拓扑和动作因果变成无歧义的视觉条件。

## 2. 成熟产品的共性机制

### LTX Studio

LTX 把 Character、Location、Object 等作为可复用 Element，再把它们绑定到具体 Storyboard 和 Shot。其角色指南建议上传 5–12 张高质量图片，覆盖近景、全身、多角度和表情，优先正面、均匀柔光和简洁背景。它的完整预视化流程是先拆剧本、固定设计和镜头，再生成动画预演、迭代和交接，而不是跳过中间工件直接生成整片。

### Google Flow

Flow 用 Ingredients 管理可复用的人物、物件、地点和风格图，同时保留 Start Frame / End Frame 来控制镜头边界。官方建议参考图使用干净或分割背景、避免无关主体，并在提示中明确说明每个 Ingredient 的用途。

### Runway

Runway 将“先用 References 生成稳定静帧，再把静帧交给 Image-to-Video”做成明确工作流。其建议从高质量、中性表情、自然均匀光线的参考开始，单次图像生成最多激活 3 个 Reference。进入图生视频后，静帧负责主体、构图、光线和风格，文字主要描述人物动作、环境动作、摄影机动作、方向、速度和时序。

### 可灵公开机制

快手公开的多图参考模式支持把人物、服装、物件、场景和交互作为不同参考主体组合。这说明成熟产品处理的是“有语义的资产集合”，而不是默认一张角色照有足够信息。这些产品仍只作为方法参考，不进入本项目运行链路。

## 3. 角色是否需要三视图

### 需要的不是固定三视图，而是角色身份包

真人短剧首版的标准角色包建议为：

1. 正面中性表情面部近景，用于锁定五官和肤质；
2. 正面或三分之四角度半身/全身，穿标准服装，用于锁定身形和服装；
3. 剧本实际会用到的左或右三分之四/侧面，用于反打和半侧面镜头；
4. 仅在有背影、转身、离场镜头时添加背面；
5. 需要时再添加表情、服装变体、特征细节和声线样本。

如果某个下游系统会对整组图片训练或提取持久 Element，可以提供 5–12 张。但 H3 Reference 是有限的镜头级条件，不应把角色包的所有图不加选择地塞入一次请求。

### 不要默认传整张宫格

LocalMiniDrama 的实际开发记录明确提到，将 2×2 角色/场景合图作为下游参考时，图像模型会模仿宫格格式，也更难从合图中提取准确外观。项目后续增加了拆分面板、优先单张正面全身图、只绑定本镜头出场资产，以及“只参考外观，不复制布局”的明确指令。

因此本项目保留“角色转面表”作为设计和审片界面，但实际调用前会拆成独立图片。

## 4. 场景包比三视图更容易被忽略

对真人都市短剧，一张好看的场景定妆图不足以描述空间。场景包至少需要：

- Master Wide：空间总布局和摄影轴线；
- Reverse / OTS：正反打方向和背景层次；
- Entrance / Exit：门的位置、铰链/滑轨、可动门叶、固定面板和开合方向；
- Key Zone：收银台、过道、座位等反复出现区域；
- Lighting State：日/夜、雨/晴和实际灯光状态。

S08 证明这一层已经是当前的首要质量问题：人物身份和道具可以成立，但双片玻璃门的可动关系没有被锁定。

## 5. 道具包应记录状态而不只是外观

道具包建议包含：

- 中性产品视图和真实尺寸；
- 手持比例；
- 镜头所需的状态变化，例如灯灭/灯亮、盒关/盒开；
- 当前持有人、手别、位置和上一镜终态。

这是 S05 比较稳定的原因：录音笔的外形、落台姿态和柜台终态已被编入镜头级首帧。

## 6. 本项目的新 ReferenceSelector

上游资产库保留完整资产包，但每个镜头只选它真正需要的少量输入：

1. 根据镜头出场角色、景别和角度选角色图；
2. 根据机位选 Master / Reverse / Entrance 等场景图；
3. 只在道具可见或状态变化时绑定道具图；
4. 优先把所有身份、空间、道具和构图合成一张镜头专属首/尾帧，再走 H3 Frame 路线；
5. 需要身份/场景复用且动作边界不复杂时，走 H3 Reference 路线；
6. 不在 H3 一次请求中混用 Frame 和 Reference。

S07 的真实失败补充了一条通用组合原则：如果角色图本身已经带有明显门窗、柜台或店面等场景几何，又与独立 Location Reference 一起传入视频模型，运镜时可能出现入口复制或空间漂移。ReferenceSelector 会提醒换用干净背景的角色图，或先把两者烘进一张镜头专属关键帧；它不会禁止用户继续原 Reference 组合。S07 改用单一首帧 F1 后，15 帧抽帧未再见第二入口，仍等待完整播放审片。

本轮先不为这套逻辑增加复杂的训练管线，只用现有 `AssetVersion`、镜头媒体绑定和简单选择规则落地。

ReferenceSelector 和导演 Agent 只负责给出可解释建议，不充当生成闸门：

- 缺少某个偏好角度、Entrance Topology 或道具状态图时，提示可能造成的一致性风险和建议补充的素材；
- 单镜动作节拍过多时，建议拆镜并说明原因；
- 用户可以忽略任何此类建议，继续编译关键帧 brief 和提交生成；
- 只有请求本身无法被下游接口接受时才阻止提交，例如 H3 的 Frame 与 Reference 互斥、字段不合法或引用了不存在的项目对象。

这里的 `required reference` 只表示“达到导演 Agent 理想质量覆盖所推荐的参考”，不表示强制前置条件。

实现上也不把“5 秒最多两个动作”“出现门就必须拆镜”写成固定产品规则。确定性代码只汇总镜头时长、动作节拍、空间交互、当前参考图覆盖情况等客观信号；GPT-5.6-sol 导演 Agent 结合剧本意图、表演连续性和用户偏好，动态给出 `补参考 / 简化动作 / 换路线 / 拆镜` 等可关闭建议。用户不调用 Agent、Agent 暂时不可用，或明确忽略建议，都不影响后续生成。

当前接口边界为：

- `reference-plan/preview`：返回推荐参考图和客观规划信号，固定 `proceed_allowed=true`；
- `director-advice`：按当前镜头上下文调用 GPT-5.6-sol，返回固定可关闭的 advisory；
- `keyframe-brief/compile`：即使缺少所有推荐参考图仍正常编译；
- H3 提交端只校验真实 Provider contract，不读取 advisory 作为门禁。

## 7. S08 的默认建议

当前 S08 不再重复原有双片滑门首帧和同一段提示。先做两个不消耗 H3 的新关键帧：

- 新首帧：画面右侧只有一扇可操作玻璃平开门，有唯一门把和明确铰链；左侧为无把手的固定玻璃面板。林夏左手持录音笔，右手已接触唯一把手；
- 新尾帧：同一机位、同一门体、同一固定面板；右侧唯一门叶向外打开，林夏的右手仍作用于这扇门，左面板不动。

关键帧候选已经生成并进入用户审批。首个尾帧因额外生成第二根把手被拒绝；第二个尾帧虽只有一根红色把手，但用户完整观察发现门体悬空，且手从首帧内侧把手跳到尾帧外侧把手，因此同样被拒绝。

这不是靠增加“门不要悬空”的 S08 专用反向词解决，而是给通用多图编辑增加可选主画布：主画布是权威物理起点，其他参考只修正身份、外观或拓扑语义，不得替换主画布的机位、对象数量、机械连接、左右方向和手部接触面。新尾帧 `asset-version-9277f306cb54` 以新首帧为主画布，门扇仍连接右侧铰链，右手仍握同一红色内侧把手，当前等待用户批准。主画布不是强制模式；用户可选“不指定主画布”。

关键帧编译也不是 S08 专用模板：通用 `start_after_action_beat_order` 可声明 START 画面位于任意动作节拍边界，已完成动作不再重演，剩余动作才交给视频模型。

导演 Agent 会建议先审这两张关键帧，再生成 1 条 H3 F2 筛选样本。如果模型仍将动作作用于错误门体，会继续建议把复合动作拆镜：

- S08A：林夏拿起录音笔、转身、右手触及正确门把；
- S08B：从店外或背后看门已开，林夏跨过门槛进入雨夜；
- 用门铃、雨声 J-cut / L-cut 隐藏剪辑。

拆分后全集为 9 个镜头，仍在已确认的 8–10 镜范围内。但这是质量建议，不是硬规则；用户仍可保留原 S08、忽略拓扑缺口或拆镜建议并继续生成。

## 8. 接下来的默认验证顺序

1. 周衡左三分之四参考、Entrance Topology 以及 S04/S06 候选已经通过；
2. S07 旧 Reference 候选已因双入口被拒绝；新 F1 候选抽帧未再出现第二入口，等待用户完整播放审片；
3. S08 新首帧与主画布尾帧已经生成，等待用户审批；两个旧尾帧已拒绝；
4. 默认在新关键帧批准后提交 1 条 S08 H3 F2，再根据结果建议保留 F2 或拆镜；用户可随时跳过这一建议并直接提交；
5. 完成单集时间线后，再统一验收跨镜声线、字幕和音乐，不因当前口型可用就提前宣告整集音画稳定。

## 9. 证据边界

- LTX、Flow、Runway 和可灵的公开指南用于提取制片方法，不代表本项目使用它们的闭源产品；
- LocalMiniDrama、ViMax、Toonflow 和 LTX Desktop 的结论来自固定源码快照；
- “参考资产包”是已采用的工作流结构；它对 H3 的具体稳定性增益仍需用 S04/S06/S07/S08 固定镜头实验验证。
