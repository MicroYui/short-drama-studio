## 3. 被替换的旧决定

- “创作 / 剪辑”双工作区及可编辑语义画布取消。初版改为“剧本 / 分镜 / 镜头 / 成片”四页；用户本轮允许有依据调整后，当前建议合并分镜与镜头为同一工作区，形成“剧本 / 镜头 / 成片”三入口，尚待确认。
- 节点详情改为场次、分镜、镜头和媒体详情；通过人物、场景和素材选择器维护原有语义引用。
- 顶部历史、独立导出导航撤下；导出进入成片页，制作记录进入右侧任务详情。
- 共享资产的“版本采用、旧版保持、挑选范围升级”取消，直接编辑当前共享对象。相关位置显示当前内容；已经生成的视频仍需实际重生成才能改变画面。
- 产品不再建设版本管理界面或新的版本框架。既有工件编号、实验文件和媒体来源先兼容保留，不在界面简化时顺手删除。
- 不再把 ComfyUI 移植作为四阶段页面的先决条件。它仍是相关媒体中的高级入口，接入顺序按完整产品需要安排。

## 4. 继续保留的决定与内容

- 单用户本地桌面，一个项目可含多集；项目共享人物、场景、道具、声音，各集分别创作、剪辑和交付。
- Agent 常驻右侧；当前集和选中内容决定下一条消息的默认范围，用户明确文字优先。切换浏览位置不改变已派发任务。
- 允许用户与 Agent 并行工作，默认保留用户已经生效的修改；不整页遮挡、不静默覆盖。
- 自动保存及编辑器常规撤销/重做；只用满足并发保存所需的内部更新检查，不要求用户处理版本。
- 支持用户外部生成素材。Provider 无法生成时说明需要什么、先发哪个说明和哪张参考图，收到后继续。
- 右侧任务有暂停/继续、问题处理和详细 Trace；保留实际模型、推理强度、调用、时间、上下文规模及供应商提供的用量。
- 现有剧本、分镜、媒体、最终成片和实验全过程记录继续保留。制作记录不是产品内容版本管理。
- Skills 描述制作方法，风格由项目决定，Tools 提供可执行能力。内容页面不把 Agent 限制成固定阶段状态机。
- LTX 只复用非模型编辑功能；当前视频生成继续使用已接入的 H3，图片与声音继续使用各自已接入 Provider。

## 5. 待通过新页面讨论的细节

新方向已由用户明确提出，以下是供本轮查看的推荐细节，尚未作为整套方案的最终确认：

1. 镜头与成片使用同一条本集时间线。“剪辑镜头”定位并放大该段，“剪辑成片”展开全片；中央打开 LTX，右侧 Agent 保留。

3. 剧本以“完成一个场次就出现”为基本实时体验，生成中的文本在可用时另外预览；已提交正文不被未完成的结构化输出覆盖。
4. 左侧固定“项目资产”入口，内容页显示本集使用的名称、缩略图与缺项；全项目、本集、当前引用是同一份清单的筛选。人物等核心对象与实际图片、视频、音频分开查看；素材库降为导入来源。
5. 主推“剧本 / 镜头 / 成片”三个内容入口。同一镜头工作区同时承载完整分镜设计和实际视频，宽屏并列、窄屏在同镜详情切换，保持同一镜号与选择；源视频可能覆盖多镜，详情保留生成编组与采用范围。
6. 一句话输入可以提出不同交付目标，Agent 达到当次目标后收尾。完整视频目标才持续推进到成片，完整剧本目标写完即停；定向修改结合原任务和最新意图决定后续动作。

## 7. 本轮四点反馈与进一步纠正

用户提出的四点原意完整保留：

1. 要看真实数据下分镜究竟是什么，尤其是记忆中形如 `[1–3s]` 后接完整详细描述的内容，不能只看简化示意。
2. 当前资产把控不清楚，看不到到底有哪些资产，需要从产品角度重新设计。
3. 分镜与镜头的边界、细节和整体使用逻辑还不清晰，应按普通人的实际使用路径重新梳理。
4. 期望可以从一段话开始，观看 Agent 实时写剧本并逐步完成视频；期间可以指定某个分镜或剧本提出修改，Agent 自行修改、回复用户并推进任务。

用户随后纠正执行边界：**要求“生成完整剧本”时，写完剧本就自动停止并回复；要求完整视频时，才持续到成片。** Agent 理解当次自然语言目标自行判断，不做固定四阶段流水线、关键词或正则路由，不要求用户先选“停止阶段”。局部修改后是否继续同样取决于原任务和最新意图；用户说只改剧本就不能自动重做视频。

### 7.1 对应解决方案

| 问题 | 当前推荐方案 | 边界与状态 |
| --- | --- | --- |
| 看不懂真实分镜 | 分镜展开完整动作、运镜、对白、声音及带时间的设计；区分叙事镜头、生成编组、Provider 请求和实际媒体 | 使用真实案例解释，具体页面呈现待讨论 |
| 看不全资产 | 固定项目资产入口；内容页露出本集资产名称、图和缺项；全项目/本集/当前引用筛选同一清单 | 项目工具，不是额外必经阶段，不建设第二套状态 |
| 设定与文件混杂 | 核心资产按人物、场景、道具、声音组织，尚无文件的所需对象也显示；所有媒体按图片、视频、音频查看并关联用途 | 设定、不同视角和生成文件有清楚关系，不引入版本树 |
| 分镜与镜头重复 | 合在同一镜头工作区：选中一镜就看该镜准备如何拍、引用什么、实际拍出了什么；设计与视频并列或在同镜详情切换 | 21 个叙事分镜对应 21 个镜头，12 段源视频默认折叠；三页建议尚待确认 |
| 像要手动点完四步 | 一段话提出交付目标，Agent 自行完成；页面展示已有成果、进度和可介入内容 | 完整剧本完成即停；完整视频才做到成片，不按页签强制执行 |
| 定向修改没有闭环 | 引用对象发出要求，Agent 修改实际内容、回复具体变化与影响、说明下一动作 | 保留用户编辑和无关工作；按最新意图决定继续或收尾 |
| 修改后相关结果过期 | 有有效整集制作目标时自行同步必要的相关媒体与成片；无此任务、仅手动更换参考时标出待更新并给定向同步入口 | 不每步确认，不把无关手动改动解释为全片生成授权 |

### 7.2 真实例子与展示约定

- 真实 `001` 组里，`001a` 是 0–4 秒点餐，`001b` 是 4–8 秒“十四元”，`001c` 是 8–13 秒质疑。镜头工作区是三个对象，各自带分镜设计与实际视频，生成组详情展示它们合成的一段计划。
- 该组计划采用 13 秒，H3 实测源视频为 13.67 秒，后期取其中 13 秒。片段内时间、源视频时长和成片使用范围分别标明。
- 真实案例 21 镜计划与 21 镜结果沿用同一镜号，底层 12 段源视频映射折叠到详情，不把原始文件数当作用户看到的镜头数。
- 详细字段、原文和证据入口见 [真实分镜、镜头与资产说明](storyboard-shot-and-asset-explainer.md)。

### 7.4 用户允许调整四页后的当前主推方案

用户明确允许有理有据调整原“剧本 / 分镜 / 镜头 / 成片”四页，不应把四页数量当作不可改变的约束。当前据此主推 **“剧本 / 镜头 / 成片”三个内容入口，另有固定项目资产工具**，这是本轮提出的方案，不代表用户已经接受三页布局。

- 镜头工作区只有一份按场次组织的镜头列表。一次选择后，查看该镜的完整分镜文字、逐时段描述、引用资产和真实视频。

- 分镜表仍可整体阅读、编辑和导出，只是不占一个独立主阶段，也不要求用户先完成确认才生成视频。

## 9. 镜头正文的资产绑定与悬停预览

用户指出仅显示资产总览仍不够：镜头或视频生成说明需要 `@` 对应图片，必须看得出在文案什么位置使用什么资产。随后明确要求鼠标移到引用上即可看到图片预览。
